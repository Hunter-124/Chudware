## 1. Screen / state map — the six surfaces

Every panel implements the same seven-state contract: `gateway-unreachable`, `lane-degraded`,
`unknown`, `empty`, `populated`, `observer`, `unsaved`.

- `gateway-unreachable` — body replaced by a sticky notice; no cached row is ever shown as live.
- `lane-degraded` — affected fields forced to unknown; names `reconnect|gap|ring_evicted|chain_break`.
- `unknown` — em-dash + `why`; never zero, never blank.
- `empty` — names the next action.
- `observer` — commands disabled; names the command owner.
- `unsaved` — blocks enqueue.

## 3. Canonical `FreshValue<T>` render rules (sole external freshness shape)

One definition, UX-owned, consumed verbatim by every domain (DoD 4; gateway §3.2 mirrors it as
`chudware::device::FreshValue` in `core/manufacturing/fresh_value.h`; a second envelope is a
contract-test failure):

```
FreshValue<T> = { v: T | null,
                  state: "ok" | "unknown" | "stale" | "refused" | "unsupported",
                  t_mono_ns, seq, age_ms, ttl_ms, src, why,
                  last_ok?: { v, t_mono_ns, seq } }
src ∈ "probed" | "declared" | "assumed" | "simulated" | "advisory"
```

Render/admission rules (final, post-Amendment-1 and C8):

1. `v` is null unless `state=="ok"`. A non-ok value is rendered em-dash + `why` — never zero, never
   blank, never the last number repainted as current.
2. `last_ok` is display-only, visibly demoted (“last good `<v>` at `<t>`”), and gates nothing.
3. Non-ok requires `why`; `age_ms > ttl_ms` renders stale; a detected sequence gap forces `unknown`
   with `why:"sequence gap <a>..<b>"`.
4. `ok && probed` **admits** a value to Stage-1 gate evaluation (plus verified `execute` capability
   for execute-side subjects); admission is necessary and **never sufficient**. Stage-2 guards
   discriminate within admitted values; the UI renders the rejecting stage and guard **by name**.
5. `simulated`, `advisory`, `assumed`, `declared` never enter approval. Simulated conclusions are
   context only (DoD 14); only gateway-recorded procedural facts bound to artifact/config/seq may gate
   (and only where the guard's `accepts.admission` lists `procedural_fact`; never for an execute-side
   subject — gateway §24.3(i)).
6. **Non-decaying durable rows (C8 ruling, §12.2):** a journaled authored row (capability report,
   durable artifact row) is published wrapped with `ttl_ms: null` and `state:"ok"`; it does not render
   stale by wall clock and is corrected only by an explicit invalidation/supersession notice (§9).
7. Host identifiers: `mfg::Fresh<T>`, `parseFresh<T>()`, `ui::mfg::drawFresh(label, fresh, unit)` —
   the sole Fresh renderer lives in `mfg_widgets.cpp`; nothing else formats a freshness envelope.
8. Twin internal state stays `{tick, dt_ns, stale_ticks, quality}`; the Gateway republisher stamps
   `t_mono_ns/seq/age_ms/ttl_ms` and sets `src:"simulated"`, which never satisfies approval.

## 5. Device / run / approval mirrors (`mfg_mirror.*`)

Read-only typed projections; the GUI computes no transition, verdict, or binding. All fields the GUI
paints are `FreshValue`-wrapped (non-decaying durable rows per §3.6). Gap/epoch handling: on
`mfg.device.resync{reason:reconnect|gap|ring_evicted|chain_break}` or a lane-epoch bump, the mirror
drops affected fields to `unknown`, records a visible audit-log break, and never back-fills.

**`MfgDeviceMirror`** (per `device_id`): `machine_class`; `FreshValue<DeviceState>`;
`FreshValue<ControllerSnapshot>` (raw vendor payload retained, never re-parsed); `CapabilityReport`
rendered through the wrapper (§3.6); `lease{owner,role,ttl_ms}`; `transport{kind,endpoint_id}`; and
the Gateway-owned **execution-autonomy fact** (`streaming_host` vs `autonomous_device`) that selects
the stale-telemetry template (§10). Template selection uses this fact, never inferred transport kind.

**`MfgRunMirror`** (per `run_id`): `RunState`; `approval_id`; `artifact_hash`; `initiator{kind,
identity}`; `timeline_from_seq` (journal rows, append-only, `gap` rendered as a visible break);
`FreshValue<ControllerSnapshot>` while live; `progress` (freshness-wrapped); `hold_reason`
(`telemetry_stale` on streaming hosts); alarm history; pending `state:"unknown"` command acks
(unresolved, no retry). A run whose monitor lane is lost on an autonomous device stays `running` with
monitor `unknown` and opens a blocking `monitor_lost` AttentionItem — it is never rendered stopped.

**`MfgApprovalMirror`** (per `approval_id`): the frozen `ApprovalBinding` verbatim (gateway §8:
machine identity/fingerprint, artifact hash/kind/post-profile, job/setup revision,
tool/fixture/WCS snapshot, preflight evidence refs + gate report ref, approver, expiry,
`exercisable_by`, nonce state, `max_starts:1`, attendance, spindle authority). Dialog states
`gathering|blocked|ready|waivers-present|expired|superseded`. Live mode reads this mirror only (via
`mfg_approval_describe`), never editable planning state. Falsification clears the binding and every
dependent row; supersession invalidates the open dialog and names the moved input.

## 6. Offline vs Live truth boundary

- **Mode is explicit and never implicit.** Default `OfflineSimulation`. Live requires one selected
  device plus an explicit command-ownership act (`mfg_device_claim{role:"commander"}`). Opening a
  panel, connecting a device, or observing a run never changes mode. Observer role is a first-class
  state, not a degraded commander.
- **Offline truth:** computed verdicts over simulation evidence only; the rail keeps the offline CAM
  bodies verbatim; plate preview is request-id-keyed and offline-only. Offline verdicts are
  advisory/simulated and never gate execution (DoD 14).
- **Live truth:** the Live banner, HUD, and Run tab read **only the frozen approval binding**
  (DoD 3). Editing the job mid-run cannot change what the live surface claims; the offline tree
  instead flips to **“Verification was for rev N, tree is at rev M.”**
- **The verdict word is unrenderable without its check set.** Verdict is computed, revision/artifact
  bound, flips to unknown on any bound-input edit, and any disabled required check forces
  `incomplete`. This permanently converts the existing `optHolder=false` → `VERIFIED` lie
  (`cam_panel.cpp:78`, `:943-958`) into a self-describing gap: **“Incomplete verification — holder
  clearance not checked.”**
- **Stop is never gated on freshness or mode.** Hold/Stop/Abort remain visible and sendable when
  telemetry is unknown or the lane is gapped, with the standing caption in §10.

## 7. Tier-0 entry-point register (8 refusals)

Completing rule: **“Tier 0 must be inexpressible, not invisible.”** A Tier-0 refusal produces no
object and no preflight row, but its action entry point MUST remain visible and name the missing
prerequisite. Canonical copy: **“Cannot create a run for this device: `execute` capability is absent
(monitor-only). This device is not a run candidate.”** Closing invariant: **“A guard that happens to
catch a prerequisite violation is not a substitute for refusing to construct it.”** (`PREREQ` rows
never become `not_applicable`; missing evidence fails — DoD 6.)

| id | refusal | action entry point that renders it | missing prerequisite, verbatim | artifact-dependent? |
|---|---|---|---|---|
| T0-1 | `execute` not verified | Fleet device actions; Queue > Create/Enqueue run | “device `execute` not `verified` → no run request; a monitor-only device is not a candidate” | no |
| T0-2 | `transport` not probed | Queue > Stage/Enqueue run | “device `transport` not `probed` → the artifact cannot be staged, so there is no run to approve” | no |
| T0-3 | unsupported dialect/controller pairing | Artifact/device pairing; Queue > Create run | “artifact dialect / device controller flavor unsupported pairing → no run request for that pairing” | **yes** — depends on the selected artifact dialect/output format |
| T0-4 | unsupported automatic tool-change strategy | Queue > Create run for the selected artifact/device | “artifact demands automatic tool change on a device with no tool table → no run request” (`tool_change_strategy_supported`) | **yes** — single-tool or explicit-M0 artifacts classify differently |
| T0-5 | no immutable registered artifact hash | Verification > Request approval; S4 run-approval entry | “no immutable registered artifact hash → no approval request” | no — always a prerequisite of approval |
| T0-6 | no writable offset mechanism | Inspectors/Metrology > Create offset proposal; S4 offset-review entry | “no writable offset mechanism on the device → no offset proposal” (Metrology's Grbl tool-table case) | no |
| T0-7 | command ownership absent | Every Live HUD/Run command entry point | “command ownership not held → no command request constructible; the surface is observer-only” | no |
| T0-8 | `safety_integration` inexpressible | Fleet capability matrix and every stop surface; permanent standing caption, no control | “`safety_integration` → permanently inexpressible; no surface exists at all, which is why it is a standing caption and not a disabled control” | no |

**Artifact-dependent prerequisite table (UX rows, composed with gateway §9).** Artifact-dependency is
computed by `tier0::classify(action, artifact_kind, machine_class)` and returned to the UI, which
renders e.g. “Start is unavailable: capability.execute is `assumed` (missing level: execute) —
highest passed emulator stage is E3.” UX-rendered artifact-dependent rows: T0-3, T0-4 above, plus the
gateway rows the same entry points display: `post_profile.bound` (required for `nc`; the `print_job`
shape substitutes slicer-profile hash), `attendance.attested` (mode set machine-class-derived),
`spindle_authority.satisfied` (**omitted from the required set entirely** for `fdm_printer_*`
artifacts — a machine-class property, not a `not_applicable` row), `wcs.established_this_setup`
(required for `nc` on router/mill; `print_job` equivalent is `bed_origin.declared_by_firmware`), and
`tier0.exercisable_by_exceeds_policy` (construction refusal when a job requests `human_or_agent` above
the device ceiling — §11). The register must be total over `action × artifact_kind × machine_class`;
`test_mfg_tier0.cpp` asserts totality and that no PREREQ row is produced as `not_applicable`.

## 8. Compound-check register — downgradable subconditions

Final frozen rule: **“THE SUB-CONDITION DOWNGRADES, THE CONDITION DOES NOT.”** UX has exactly one
legitimate downgradable sub-condition — door/interlock monitoring within `no_active_alarm` — and zero
whole conditions that may be `not_applicable`. Three dispositions, final:
`not-required-for-this-machine-class` is a property of the class and produces **no row**;
`not_applicable` is a corroborated missing sensor sub-condition and never counts as pass; `fail` is
missing evidence. **“Absence of evidence is a failure to PROVE, not an inapplicable check.”**

| compound check | non-downgradable part | downgradable / absent part |
|---|---|---|
| `fixture_present` | Fixture fact: prerequisite; from sensor corroboration or explicit human setup attestation in the binding. | Sensor corroboration may be absent; absence never removes the fixture-fact requirement. |
| `nc_artifact_staged` | File presence on the device: prerequisite; pass/fail. | Checksum verification may downgrade when the device cannot checksum. |
| `no_active_alarm` | Alarm state: every runnable device must report it; missing is `unknown`/fail at Stage 1. | Door/interlock sub-state may be visibly absent when no switch is fitted and the capability set corroborates that absence (the one legitimate `not_applicable`). |
| `envelope_check_performed` | Arbiter computation performed, gateway-recorded, bound to artifact hash + seq. | Profile provenance may be `probed` vs `declared`; `declared` renders as weaker evidence, never converted into a passable conclusion gate. |
| verdict | Every check required for the machine class must be enabled and clean. | Checks outside the class's required set are absent entirely, never `not_applicable` rows (a laser has no holder check). |

**Pass-direction table columns, verbatim (the contract-test shape, DoD 19):**

`guard | stage | an input that makes it FAIL | an input that makes it PASS | prerequisite-or-corroborating and whether that is artifact-dependent | downgradable sub-parts`

## 9. Run-approval gate source set, with pass/fail fixtures for every gate

`source_is_probed`, `capability_execute_verified`, `transport_connected`, `snapshot_seq_contiguous`,
plus UX's own two unsatisfiable gates sourced solely from `src:"simulated"` twin evidence.
`tier_at_least_q2` survives precisely because it discriminates within admitted probed values.

**Waiver-rate surface.** Named waivers are durable `{by, reason, at_seq}` (DoD 7). The Verification
tab renders the aggregate waiver rate **per guard** from `mfg_event_query{…, waiver_rates:{guard:
rate}}`, so a guard waived on effectively every recent run is visible (DoD 8). A waived row names
actor and reason adjacent to the verdict; waivers never change a `fail` into a `pass` in the gate
report — they are a separate, visible disposition, and `waivers-present` is a first-class S4 state.

**Invalidation seq application (DoD 9).** Every painted result carries its establishing durable `seq`;
every notice carries `at_seq`; the mirror applies a notice **only** to rows with `seq <= at_seq`, so
out-of-order delivery and replay are idempotent no-ops and a row with `seq > at_seq` survives.
Consumers branch on `class`, never on event-name tables: `class:"falsified"` clears the value (alarm
lane; a claim that cannot be re-derived is falsified, never merely dimmed); `class:"superseded"`
retains the row, points forward via `superseded_by`, and raises no alarm. Producers push
invalidations; the UI never waits for polling or TTL to correct a painted value. Frame-ordering
grounding: `st.rpc.drain()` runs **earlier** in the frame than the event tick
(`engine_events.cpp:907-909`), so the mirror drains RPC results first and applies lane notices after —
a just-produced value is never cleared by a stale in-flight notice within one frame, and the
`seq <= at_seq` rule makes the cross-lane order irrelevant across frames.

## 10. Status, attention, and notification behavior

- **Status bar (S5):** persistent non-expiring attention chip in every workspace; sticky
  gateway-unreachable chip beside `daemonUnreachable` (`status_bar.cpp:213-238`); Manufacture token
  (`:341-364`) shows `Offline sim` or `<device>: <controller state>`, tinted `statusOk` only when
  fresh, `statusWarn` stale, `statusErr` on alarm.
- **Attention workflow:** durable, severity-ordered items with ack/dispose via
  `mfg_attention_ack|dispose`; blocking items (`monitor_lost`, unresolved `state:"unknown"` command
  acks) are undisposable until resolved. Global chip persists until acknowledged and routes to
  Floor > Attention. Audit Log tab is append-only; a lane `gap` renders as a visible break, never a
  silently continued line.
- **Toasts (S6):** pointers only; never the alarm/approval record or decision surface.
- **Safety copy and disabled-state rules:**
  - **Named-reason-adjacent:** a control is never disabled silently and never explained only by
    tooltip; adjacent copy names the missing thing, its source, and the device. E.g. **“Execute
    unavailable — `<device>` reports capability `execute` as assumed, not verified. Probe the
    device.”**; **“Start unavailable — preflight gate `fixture_present` is unknown. Unknown fails
    closed.”**; **“Commands unavailable — command owner is `<client>` since `<t>`. You are
    observing.”**
  - **Stop never gated on freshness:** persistent caption **“Software stop is a request to the
    controller. It is not an emergency stop. Use the machine's E-stop for emergencies.”**
  - **Streaming-host template, verbatim:** **“Run held — telemetry stale. The host stopped streaming;
    the machine is stopped.”** (stale telemetry holds the run, `hold_reason=telemetry_stale`).
  - **Autonomous-device template, verbatim:** **“Monitoring lost — the printer is still printing from
    its own storage. You cannot see it.”** (`run_state` stays `running`; monitor unknown; blocking
    `monitor_lost` attention opens). The words **“connection lost”** appear nowhere.
  - **Resume copy:** **“Resume requires a fresh approval. The machine was in `<state>`; position and
    tool state are unknown until re-established.”** No binding reuse across reset, hard limit, alarm,
    disconnect, or power loss (DoD 13); `held → resuming` only under the gateway §6.2 five conditions,
    otherwise the run is `abandoned`.
  - **Proposal copy:** **“Proposal — not authorized. Approving still requires the standard preflight
    and your identity.”** Exact deterministic command intent shown; proposals never grant
    authorization; stale proposals are marked, not silently refreshed.

## 11. Selectable `exercisable_by` flow (previously open — now decided)

DoD product choice 1 and gateway §8.1 settle the item the freeze left open: **runtime approval is
selectable per job: `human_only` (default) or `human_or_agent`, bounded by commissioning policy.**

UX flow, final:

1. S4 run-approval mode renders an `exercisable_by` selector with exactly two options —
   **“you only”** / **“you, or the agent on your behalf”** — defaulting to `human_only`. The selector
   is a real control (selectable ruling), never hidden in advanced options.
2. The device's ceiling (`mfg_policy_get(device_id).max_exercisable_by`) is displayed beside the
   selector. Requesting `human_or_agent` above the ceiling is refused **at construction**
   (`tier0.exercisable_by_exceeds_policy`, rendered at the approval entry point per §7) — never
   silently downgraded.
3. The issued binding's final `exercisable_by` is thereafter a first-class immutable fact, shown in
   the Run/Queue rows and the Live HUD.
4. Agent exercise is nonce exercise, not authorization: the arbiter revalidates the full binding,
   starts, burns the nonce, and journals `initiator{kind:"human"|"agent",identity,seat,at_seq}` plus
   the burn seq on every attempt. The run header shows `initiated_by:human|agent`, agent run id,
   approval id, and visible nonce burn **“exercised at `<t>` by `<actor>`”**.
5. The agent may never approve itself, resume after alarm/reset/disconnect, jog, home, zero,
   override, unlock, bypass interlocks, or issue safety commands; those verbs have no MCP tool and no
   UI affordance routed to an agent-callable path (DoD 12/15).
