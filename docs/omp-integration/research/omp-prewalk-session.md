# OMP `prewalk` + session/state persistence — research dossier

## 1. What `prewalk` actually is

**Prewalk is real and exists exactly under that name.** It is a one-way, mid-session model hand-off mechanism, not a search/exploration "walk" (no relation to game-tree/AST "prewalk" senses). Its purpose: run the *start* of a task on a strong/expensive model until a todo plan exists and the first edit/write lands, then permanently switch the running session to a fast/cheap model for the remaining implementation — cutting cost/latency on long agentic runs without sacrificing planning quality.

- History: it replaced an earlier `--reasoning-slide-*` flag family and a short-lived `--prewalk-boomerang` variant (removed) — `packages/coding-agent/CHANGELOG.md:203,239` (CAD/scratch/omp-src).
- Core state machine: `AgentSession` in `packages/coding-agent/src/session/agent-session.ts:770-815, 1748-1757, 2243+`.
  - `Prewalk` interface: `{ target: Model; thinkingLevel?: ConfiguredThinkingLevel }` (`agent-session.ts:781-783`).
  - Trigger tools: only `edit`/`write` (`PREWALK_ACTION_TOOLS`, `agent-session.ts:495-498`) — `bash` deliberately excluded (it's also used for exploration and fired false triggers turn-1).
  - Todo-gate: switch fires at the first edit/write **after** a `todo` call has landed (`#prewalkTodoSeen`, `agent-session.ts:1754-1757`); sessions with no active todo tool skip the gate.
  - Mechanism: a hidden "plan nudge" message (`prewalk-plan.md`) is injected at start asking the strong model to plan + commit a todo list; once the gate opens and an edit/write fires, a "continue" nudge (`prewalk-continue.md`) and a "verify before finishing" checklist (`prewalk-checklist.md`) are steered in, and the model is swapped. The plan nudge is scrubbed from context at the switch point (agent-session.ts:277-286, 474-502).
- **Invocation surfaces** (three independent layers, same underlying mechanism):
  1. CLI/session-level: `--prewalk` / `--prewalk-into <model>` / `--no-prewalk` (`cli/args.ts:31-33,240-243`; `commands/launch.ts:37-46`; resolved in `main.ts:934-955`). Default target: `@smol` role alias (`DEFAULT_PREWALK_TARGET`, `config/model-resolver.ts:1097`).
  2. Settings: `prewalk.enabled` (default off) — `config/settings-schema.ts:425-434`.
  3. Slash command: `/prewalk` arms it on a running session at runtime, works even without the `--prewalk` flag (`slash-commands/builtin-registry.ts:465-486`, calls `session.armPrewalk(...)`).
  4. Per-*subagent* prewalk: agent-frontmatter field `prewalk: true|"<model>"`, or settings override `task.agentPrewalk` (toggled per-agent from the `/agents` dashboard with the `P` key), or the generic `task` agent's own `task.prewalk` toggle (default off). Resolution: `resolveAgentPrewalkPattern()` in `config/model-resolver.ts:1114-1126`, applied in `task/executor.ts:2308-2334`. Read-only/exploration agent variants explicitly strip `prewalk` (`task/index.ts:1263-1267`) because the plan/checklist nudges assume edit tools a read-only toolset doesn't have.
- UI surface: status-line "Prewalk" annotation while armed (icon 🏃, `theme/theme.ts:305`; `status-line/segments.ts:210-214`; `status-line/component.ts:1062-1066`), and an `/agents` dashboard column showing on/off + resolved target (`modes/components/agent-dashboard.ts:295,313-329`).
- Known bugfix history: prewalk repeatedly continuing after a bash-only completed task (e.g. `commit`) — fixed, issue #5551 (`CHANGELOG.md:22,100`).

**Inputs**: starting model + thinking level, target model/thinking override, todo-tool presence, edit/write tool calls.
**Outputs**: a session that silently swaps its active model+thinking level exactly once, with injected system nudges shaping the strong model's plan-then-start behavior and the fast model's verify-before-finish behavior.

## 2. OMP session/state persistence architecture

Directory: `packages/coding-agent/src/session/` (39 files). Key modules:

### Storage backend abstraction (`session-storage.ts`)
- `SessionStorage` interface abstracts over `FileSessionStorage` (JSONL on local disk), `MemorySessionStorage` (tests), `RedisSessionStorage`, and `IndexedSessionStorage`/`sql-session-storage.ts` (SQL-backed, for multi-writer / hosted deployments) — `session-storage.ts:43-77`, file list confirms `redis-session-storage.ts`, `sql-session-storage.ts`, `indexed-session-storage.ts`.
- **Atomic write contract**: `writeTextAtomic(path, content, {commitGuard})` — write to a `.{name}.{Snowflake}.tmp` temp file, then `fs.renameSync` (POSIX atomic rename) to the final path; guard+rename happen with **no await between them** specifically to close a race window where a concurrent synchronous rewrite could be clobbered by a stale staged body (`session-storage.ts:253-286`, comment at 263-266). Windows EPERM-on-rename is handled with a fallback replace path (`#replaceSessionFileAfterEpermSync`).
- `writeTextSync` (full-file rewrite, e.g. rewriting the whole JSONL after a branch/compaction op) uses the same temp-file-then-rename pattern (`session-storage.ts:169-194`), with cleanup of the temp file on failure and an EPERM direct-write fallback.
- Append-only writer (`FileSessionStorageWriter`) keeps one fd open for the session's lifetime and does raw `fs.writeSync` loops handling short writes; a `FinalizationRegistry` closes leaked fds if the writer object is GC'd without `close()` (`session-storage.ts:79-156`).

### Format (`session-entries.ts`, `session-migrations.ts`)
- Sessions are JSONL, one entry per line, entries form a **DAG** (`parentId` links), not a flat array — supports branching/rewind (`SessionEntry`, `session-manager.ts` `SessionEntryIndex` builds an id→entry map + children adjacency + "leaf" pointer, `session-manager.ts:194-318`).
- `CURRENT_SESSION_VERSION = 3`; `migrateToCurrentVersion()` upgrades old-version files on load (`session-migrations.ts`, referenced `session-loader.ts:14,289`).
- Optional fixed-width (256-byte) "title slot" as physical first line of the file, updated in place via `updateSessionTitle` (`session-storage.ts:196-213`) — lets the title change without rewriting the whole file.

### Load path / corruption tolerance (`session-loader.ts`)
- **Lenient JSONL parsing**: `parseJsonlLenient` — malformed lines are tolerated.
- Streaming load for files ≥8MiB (`STREAM_LOAD_THRESHOLD_BYTES`, `session-loader.ts:24,104-178`) using `Bun.JSONL.parseChunk`; on a parse error mid-stream it **skips past the next newline and continues** rather than aborting the whole load (`session-loader.ts:126-133`) — tolerates a torn/corrupt record without losing the rest of the session.
- Header validation: first entry must be `{type: "session", id: string}` or the whole file is treated as empty/unreadable (`session-loader.ts:220-225`) — a hard corruption-detection gate.
- `loadEntriesFromFileStream` explicit fallback: `isEnoent` → returns empty session rather than throwing (`session-loader.ts:172-175`).

### Persistence-time safety (`session-persistence.ts`, `turn-persistence.ts`)
- `prepareEntryForPersistence()` runs **synchronously in one tick** specifically so "an OOM/SIGKILL landing right after a persist call returns cannot lose the entry" (`session-persistence.ts:75-79`) — oversized text truncated, oversized images externalized to a content-addressed blob store (sha256-keyed, `blob-store.ts`) *before* the JSONL line referencing them is appended, guaranteeing the blob is in the page cache before the pointer exists.
- Signed/encrypted content blocks (thinking signatures, redacted-thinking, OpenAI Responses `encrypted_content`) are **never truncated** even if oversized — truncating would desync them from their provider-side signature and break replay (`session-persistence.ts:96-129`).
- `turn-persistence.ts`: computes a **stable persistence key** per message (role-specific discriminators: timestamp+provider+model+responseId+stopReason for assistant, timestamp+toolCallId+toolName for tool results, etc.) so re-persisting an already-appended turn (e.g. after a crash/resume mid-turn) is idempotent — `planTurnPersistence()` returns `{kind: "ok", toPersist: [...]}` or `{kind: "out-of-order", ...}` and the caller **bails rather than risk splicing a stale message between newer entries** (`turn-persistence.ts:100-142`).

### Session identity, resume, breadcrumbs (`session-manager.ts`, `session-paths.ts`)
- `resolveBreadcrumbToInteractiveRoot()` walks a "last session" breadcrumb up to its top-level parent (subagent sessions live nested under `<parent>/<agentId>.jsonl`) so `--continue`/`-c` resumes the real conversation, not an orphaned subagent transcript, and defends against "poisoned" breadcrumbs left before a bugfix (`session-manager.ts:97-116`).
- `DRAFT_ONLY_SESSION_MARKER` + `isDraftOnlyMetadataEntry()`: sessions that only ever received UI-selector metadata (mode/model/thinking/tier changes with zero real conversation) are recognized as non-resumable-worthy so they don't clutter session listing (`session-manager.ts:77,165-182`).
- Compaction summaries are versioned: superseding a compaction elides the *previous* one's summary text on load (`elideSupersededCompactionEntries`, `session-loader.ts:93-102`) but only along the currently active branch (`collectActiveBranchIds`, walks parentId chain from the last entry) — stale/abandoned branches keep their original summaries untouched.

**No explicit WAL/journal beyond JSONL append + atomic rename + idempotent turn-keys** — the append-only log itself *is* the durability mechanism (crash mid-append leaves a torn last line, tolerated by lenient parsing; crash mid-rewrite leaves the old file intact because rename is atomic and the temp file is orphaned, not the target).

## 3. CAD's equivalents

CAD has **no JSONL chat-session-file analog**; instead two adjacent but distinct persistence layers:

### `services/agent/ledger.py` — Design Ledger (closest analog to OMP's session log)
- Schema `aicad.ledger/1`. Storage: `<cache_root>/runs/<run_id>/ledger.json` (compact materialized state) + `ledger.jsonl` sidecar (append-only raw events) — `ledger.py:9-16`.
- **Same core pattern as OMP**: append-only event log, state is a **pure replay/materialization** of events (`_materialize()`, `ledger.py:218-223`), never trust stored state directly — `load()` always rebuilds from events (`_load_from_jsonl`, `ledger.py:278-281`). This mirrors OMP's philosophy (session state = replay of entries) but CAD's ledger is coarser-grained (design decisions/requirements/dimensions/build nodes, not full chat turns).
- **Corruption tolerance**: `_read_events_jsonl()` catches `json.JSONDecodeError` per-line and **skips a torn last line from a mid-write crash** (`ledger.py:270-273`) — directly analogous to OMP's lenient JSONL parse-and-skip.
- **No atomic-rename write path found** in the excerpt read — appends are plain `f.write()` (`_seed_events_jsonl`, `ledger.py:293-301`); unlike OMP's `writeTextAtomic`, no temp-file+rename is used for the `ledger.json` snapshot rewrite (this file only shows the JSONL seed path; the `ledger.json` snapshot writer needs deeper reading past line 300 to confirm, but the class docstring implies snapshot is written directly, not via atomic rename).
- Legacy migration path exists (whole-document `{"events":[...], "state":{...}}` format auto-migrates to sidecar JSONL on first append) — same idea as OMP's `migrateToCurrentVersion`.

### `services/agent/workspace.py` — per-document lease + event stream (no chat persistence)
- Per-doc JSONL event streams at `<cache>/runs/<run_id>/docs/<doc_id>/events.jsonl` (`workspace.py:14-16,76-77`), append-only, **write errors are silently swallowed** (`except OSError: pass`, `workspace.py:272-273`) — weaker guarantee than OMP (OMP's writer records the error via `getError()`/`onError` callback so callers can surface it; CAD's workspace event stream has no equivalent surfacing, it just silently drops the write).
- Thread-safe single-writer/multi-reader lease registry (`LeaseRegistry`) with a HARNESS-ONLY `steal()` recovery path for dead/revoked agent owners (`workspace.py:180-192`) — a different problem (concurrent multi-doc ownership) than OMP's single-session persistence, no direct analog in OMP.

### `services/agent/session_cmds.py` — **not a persistence layer at all**
- Pure host-facing transforms (`/handoff`, `/btw`, `compact`) over a `messages[]` list the **host** owns; explicitly stateless — "Host-facing pure transforms... Inputs are never mutated" (`session_cmds.py:3-7`). No file I/O, no session store. The actual chat transcript persistence lives in CAD's C++ host (not found in the Python agent tree; would need a host-side scout to confirm the storage format — this dossier only covers the Python agent side per the assignment scope, C++ host session store was not located under `services/agent`).
- `local_runtime.py:343-345` shows the **one place CAD already does atomic rename-based writes**: `routing.yaml` provisioning uses `tempfile.NamedTemporaryFile` + rename specifically "to avoid corruption" (`local_runtime.py:408-410`) — proves the team already knows and uses the pattern OMP applies session-wide, just not yet for the ledger/session store.
- `config.py:38-40`: `_cfg_cache` comment explicitly calls out avoiding "corrupt[ing] the cached dict" via `save_config`'s read-merge-write, a narrower defensive pattern, not atomic-file-level.

### Guardrails / auto-checkpoint (`services/agent/guardrails.py`, `agent_turn.py`)
- `auto_checkpoint` (WI-12) is a **safety mechanism before destructive tool calls**, not a session-persistence checkpoint: `take_auto_checkpoint()` calls an injectable `checkpoint_fn` (doc_checkpoint / plm_checkpoint) before a destructive tool executes, and **blocks the destructive call if the checkpoint fails** (`guardrails.py:817-836`, `MSG_CHECKPOINT_FAIL` at line 78). This is CAD's analog to "don't lose state," but it's a pre-mutation snapshot of the *CAD document*, not the agent conversation. It's architecturally similar in *intent* (never let a destructive op proceed without a recovery point) but targets PLM document state, not chat/session state — the user's reported "session-corruption pain" is more likely about the ledger/workspace JSONL streams (or the C++ host's own session store, unexamined here) than this mechanism.

## Summary (<300 words)

**"Prewalk" is real**, not a misremembered name: it's OMP's one-way mid-session model hand-off — start a task on a strong/expensive model, let it plan (commit a todo list via a hidden "plan nudge" message), then permanently swap to a fast/cheap model (default `@smol`) the moment the model's first `edit`/`write` call lands after that todo list exists. Trigger logic lives in `AgentSession` (`packages/coding-agent/src/session/agent-session.ts:770-815, 2243+`); it's invocable session-wide (`--prewalk`/`prewalk.enabled`/`/prewalk`) or per-subagent (agent frontmatter `prewalk:`, `/agents` dashboard toggle). It's genuinely portable to Python: pure state-machine logic (todo-gate + tool-name trigger + model swap + injected system messages), no native/bun-only dependency — recommend **PORT**, moderate effort, mainly requiring CAD's turn loop to support hot-swapping the active model mid-run.

**Session persistence**: OMP treats the JSONL session file as an append-only branching DAG log where state is *always* rebuilt by replaying entries, never trusted from a cached snapshot. Its two biggest correctness guarantees — (1) atomic writes via temp-file + `fs.renameSync`, with the guard-check and rename kept in the same synchronous tick to close a race window, and (2) lenient parsing that skips a torn/corrupt line rather than failing the whole load — are the two things CAD is most exposed on. CAD's `ledger.py` already replays events from a JSONL sidecar and already tolerates a torn last line (mirrors OMP almost exactly), but its snapshot (`ledger.json`) write and `workspace.py`'s per-doc event-stream writes do **not** appear to use the atomic temp+rename pattern that CAD itself already uses elsewhere (`local_runtime.py:408-410`, for `routing.yaml`). **Top recommendation: PORT the atomic-write pattern (S effort, zero new deps) to `ledger.py` and `workspace.py`** — this directly targets the user's reported session-corruption pain and reuses an idiom CAD's own codebase already validates elsewhere. CAD's destructive-op auto-checkpoint guardrail is unrelated to and arguably stronger than anything in OMP for document-state safety — keep it as-is.
