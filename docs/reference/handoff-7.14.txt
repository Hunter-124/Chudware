  ## Completed and live

  ### Linux remote recovery

  The “Peer ID known but vault empty” failure is fixed and verified on this Linux machine.

  Root cause:

  - Password provisioning failed, but the agent treated the peer ID alone as success.
  - A stale remote.cred.uploaded marker remained while remote.cred was absent.
  - The server vault could therefore remain empty indefinitely.

  Implemented:

  - Success now requires both the peer ID and an uploadable credential.
  - Passwords use OS-backed cryptographic randomness.
  - remote.cred is written atomically with mode 0600.
  - Forced recovery preserves an unacknowledged credential.
  - The agent retains plaintext until the API explicitly returns password_stored: true.
  - Error output cannot leak password-bearing command data.
  - Remote maintenance remains off the heartbeat-critical path.

  Live test result:

  - Wayland capture: ready
  - Input/uinput: ready
  - Rendezvous configuration: valid

  - Both local services are active.
