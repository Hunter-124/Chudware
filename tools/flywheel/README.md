# Flywheel — Training Data Store (T-H5)

Consent-filtered telemetry exporter, DVC versioning, and Argilla human-audit gate
for the AI-CAD custom-model training pipeline (Pillar 16).

---

## Architecture overview

```
AI-CAD app
  └── events.jsonl  ←  ai_artifact / ai_artifact_action / doc_semantic_diff
                       (per-run, per-doc; consent stamped at emission by T-H1)

flywheel export (user-initiated or scheduled)
  ├── Scanner:   <appdata>/AI-CAD/cache/runs/**/events.jsonl
  │              + per-doc undo journals (.cam_journal.jsonl / .ecad_journal.jsonl)
  ├── Consent gate:
  │     offline_enabled → hard OFF → nothing exported
  │     session envelope consent=off → skip session
  │     effective tier = stricter of (app_config, session_envelope)
  ├── Scrubber:  API keys, e-mail, absolute paths, usernames stripped;
  │              machine IDs hashed (SHA-256 prefix)
  ├── Derivation engine (contracts/telemetry.md §5):
  │     §5.1 SFT examples
  │     §5.2a-c Preference pairs (regen / retry-loop / undo-negative)
  │     §5.3 Correction traces
  │     §5.4 Elicitation gold
  └── JSONL shards → training/corpus/<insertion_point>/v1/shard_<ts>_<id>.jsonl

DVC (version + push/pull)
  └── training/  ←  git+DVC repo
        corpus/
          IP-13/v1/shard_*.jsonl   ← SFT + preference pairs for design features
          IP-12/v1/shard_*.jsonl   ← Elicitation gold
          unknown/v1/shard_*.jsonl ← Untagged records (insertion_point missing)
        .dvc/config                ← remote = /path/to/nas  (or s3://...)

Argilla audit gate (human-gated, self-hosted on hunter-pc)
  ├── argilla_loader.load_shards_to_argilla(shards) → queue for review
  ├── Human review in Argilla UI (http://localhost:6900)
  └── argilla_loader.snapshot_approved(out_dir, ip) → corpus/<ip>/v1/approved_snapshot_*.jsonl
```

## Training-data repo layout

The training-data store lives in `training/` (adjacent to this repo, or at a
user-configured path). It is a separate git+DVC repo — NOT committed into the main
`CAD` repo.

```
training/
  .dvc/
    config          ← remote URL (local path or s3://)
  .dvcignore
  corpus/
    <insertion_point>/    ← e.g. IP-13, IP-12, unknown
      v1/
        shard_<ts>_<id>.jsonl           ← raw exported shards (pre-approval)
        shard_<ts>_<id>.jsonl.dvc       ← DVC tracking file
        approved_snapshot_<ts>_<id>.jsonl  ← Argilla-approved snapshot
        approved_snapshot_*.jsonl.dvc
```

**Why `training/` not a separate repo?** The task notes both options. We chose
`training/` as a subdirectory for discoverability (one root, one `git worktree`),
with DVC providing the versioning and remote sync. DVC's `.dvcignore` keeps the
corpus data out of the git index.

## Provenance schema

Every training record carries a `provenance` field:

```json
{
  "provenance": {
    "source": "telemetry",
    "session_id": "<run_dir_name>",
    "artifact_id": "<UUID or null>",
    "consent": "full | meta",
    "app_version": "0.1.0",
    "ts_derived": "2026-07-02T18:00:00+00:00"
  }
}
```

And a `legal_cleanliness` field (one of):
- `"telemetry-consented"` — derived from user-consented telemetry
- `"synthetic"` — generated by the synthetic factory (T-F10)
- `"licensed-<name>"` — from a licensed dataset (e.g. `"licensed-ocp-dataset"`)

---

## Consent tiers (summary)

| Tier | Who | What's exported |
|---|---|---|
| `off` | external default; offline mode | nothing |
| `meta` | opt-in meta | event metadata only; sidecar refs nulled |
| `full` | team dogfood default; explicit external opt-in + per-project | all fields; sidecars bundled |

## Usage

### Export (user-initiated)

```bash
python -m tools.flywheel.export \
  --runs-dir ~/.local/share/AI-CAD/cache/runs \
  --out-dir training \
  --config ~/.local/share/AI-CAD/config.json \
  --app-version 0.1.0
```

Add `--dry-run` to preview without writing files.

### DVC init + push/pull

```bash
# Initialise (local NAS path — swap for s3:// when ready)
python -m tools.flywheel.dvc_init --repo training --remote /mnt/nas/aicad-training init

# Push after export
python -m tools.flywheel.dvc_init --repo training push

# Pull on a second machine
python -m tools.flywheel.dvc_init --repo training --remote /mnt/nas/aicad-training pull
```

### Argilla audit gate (requires running docker-compose stack)

```bash
# Start Argilla (one-time setup)
cp tools/flywheel/.env.argilla.example tools/flywheel/.env.argilla
# edit .env.argilla with real keys
docker compose -f tools/flywheel/docker-compose.argilla.yml \
  --env-file tools/flywheel/.env.argilla up -d

# Load shards for review
export ARGILLA_API_URL=http://localhost:6900
export ARGILLA_API_KEY=<key from .env.argilla>
python -c "
from pathlib import Path
from tools.flywheel.argilla_loader import load_shards_to_argilla
shards = list(Path('training/corpus').rglob('shard_*.jsonl'))
result = load_shards_to_argilla(shards)
print(result)
"

# After human review in Argilla UI...
python -c "
from pathlib import Path
from tools.flywheel.argilla_loader import snapshot_approved
result = snapshot_approved(Path('training'), insertion_point='IP-13')
print(result)
"
```

## DVC remote configuration

**Current default (approved by Erik 2026-07-02):** plain local/NAS absolute path.

```bash
# View current remote
python -m dvc --cd training remote list

# Change to cloud (one-line swap):
python -m dvc --cd training remote modify origin url s3://my-bucket/aicad-training-data
python -m dvc --cd training remote modify origin access_key_id <key>
python -m dvc --cd training remote modify origin secret_access_key <secret>
```
