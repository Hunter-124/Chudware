# ViewNet label sources — survey, licences, recommendation

Purpose: parts with **face/feature-level ground truth** from which geometry questions (count,
presence/side, through/blind, type, dimension ratios) can be generated for training and
evaluating the view-utility model (`contracts/geom_labels.md`, schema `chudware.geomlabel/1`).
Chudware is a **commercial product**: any source whose licence forbids commercial use, or whose
data licence is unstated, is not used to train a shipped model.

Licences were checked against primary sources on 2026-09-28 (links below). Sizes marked
"probed" were read from the live server (HTTP Range / central directory) during this survey.

## Recommendation

| Source | Use | Parts | Labels | Licence (commercial use) |
|---|---|---|---|---|
| **MFCAD** | **Primary training/eval source (default)** | 15,488 STEP | 16 machining-feature classes per face | MIT — **yes**, keep the licence notice |
| MFCAD++ | Larger superset of MFCAD; opt-in once the zip is obtained by hand | 59,665 STEP | 25 machining-feature classes per face | CC BY 4.0 — **yes**, with attribution |
| **mfcadpp_gen (ours)** | **Default; the curved-feature source** — our OCP port of the MIT MFCAD++ generator | unlimited (seeded) | the same 25 classes per face + the generator's feature instances | generator MIT (keep the notice); parts generated by us — **yes** |
| **GSL (ours)** | **Secondary, licence-clean** | unlimited (7 families) | exact owning-feature per face | Chudware-generated — **yes** |
| NIST best-view (Dutagaci 2010) | Human view-preference sanity check only | 68 meshes | 26 people's best views | NIST open licence — yes for NIST data; meshes include third-party research models |
| MFInstSeg | Blocked until rights confirmed (or regenerate with its MIT generator) | 62,495 STEP | 25 classes + instances + bottom faces | **unstated** for the data (code MIT) |
| Fusion 360 Gallery (segmentation, reconstruction) | **Rejected** for shipped training | 35,680 / 42,912 STEP; 8,625 sequences | 8 op classes per face | **non-commercial research only** |
| Text2CAD | **Rejected** | DeepCAD models + text | text prompts | **CC BY-NC-SA 4.0 (non-commercial)** |
| ABC | Not for v1 labels | ~1M models | surface-patch types only | per-document Onshape terms (mixed) |
| DeepCAD | Future op-label source after licence filtering | sketch+extrude sequences | construction sequence, no face labels | code MIT; data = Onshape per-document terms |
| CADTalk | Rejected (labels do not map) | OpenSCAD programs | semantic part names | code MIT; data unstated |
| Secord et al. 2011 | Baseline idea only (published model) | user study | view-goodness attributes | no data licence stated |

Start small: 1,500 MFCAD parts, ~1,000 GSL samples and 3,000 generated MFCAD++ parts (the
`build_manifest` default sources are `mfcad,gsl,mfcadpp_gen`; the build regenerates the whole
manifest from the sources it is given, so always pass all of them):

```
python3 -m training.viewpoint.datasets.fetch mfcad --limit 1500
CHUDWARE_ENGINE_DAEMON=0 .venv-mcp/bin/python -m training.viewpoint.datasets.build_manifest \
    --sources mfcad,gsl,mfcadpp_gen --limit 1500 --gsl-count 150 --mfcadpp-gen-count 3000
```

MFCAD is pulled file by file from GitHub at a pinned commit, each file verified against its git
blob SHA-1 (no clone). MFCAD++ cannot be fetched by a script (see its section); once
`MFCAD_dataset.zip` has been downloaded in a browser it is used with
`fetch mfcadpp --archive ~/Downloads/MFCAD_dataset.zip --limit 3000` and
`build_manifest --sources mfcadpp,gsl`. Every other zip source is fetched by HTTP Range, pulling
only the `--limit` subset.

## Sources

### MFCAD (Cao et al. 2020) — recommended (primary, default)

- Paper: Cao, Robinson, Hua, Boussuge, Colligan, Pan, *Graph Representation of 3D CAD Models
  for Machining Feature Recognition With Deep Learning*, ASME IDETC-CIE 2020.
- Repo: https://github.com/hducg/MFCAD — pinned commit
  `ef6d58a40164d5192666821ce98d0cc90e379fac` (`fetch.MFCAD_COMMIT`); repo ~190 MB,
  `dataset/step/` holds 15,488 `<stem>.step` + 15,488 `<stem>.face_truth` (1.16 GB unpacked).
- Fetch: one GitHub trees-API call lists the commit (cached as
  `raw/mfcad/git_tree.<commit>.json`), then the `--limit` subset is pulled from
  raw.githubusercontent.com and each file is checked against its blob SHA-1 from the tree.
  Measured: 1,500 parts = 3,000 files, 112.8 MB, 36 s.
- Format / labels (read from the downloaded files and the repo's `occ/dataset_visualizer.py`):
  every `ADVANCED_FACE` is named with a face id; `<stem>.face_truth` is a pickled Python list,
  entry `[id]` = class index into `FEAT_NAMES` (16 classes). The reader unpickles plain data
  only. The stem's numbers except the last are the generator's feature codes (2–5 per part) in
  the same index space. No instance labels — instances are connected same-family faces
  (contract §6).
- Licence: **MIT** (`LICENSE`, "Copyright (c) 2020 hducg"; GitHub licence API `mit`) covers the
  whole repository including `dataset/`. Commercial use allowed; keep the notice.
- CANON: contract §7 — slot/passage/step/pocket through and blind, chamfer, stock. No holes,
  o-rings or fillets (MFCAD++ adds those).
- Caveats: synthetic prismatic stock with 2–5 features, single body, every face planar (6,809
  faces of 300 parts checked).
- Measured build (2026-09-28, `--sources mfcad,gsl --limit 1500 --gsl-count 150`, 95 s wall):
  MFCAD 1,500/1,500 kept at match rate 1.0 (0 unmatched faces); 7,549 features — step_through
  1,334, passage 1,317, pocket 1,290, step_blind 887, slot_through 857, chamfer 444,
  slot_blind 420; splits 1,187 / 159 / 154. GSL 900/1,050 (all 150 `swept_pipe` dropped at 0.80,
  see GSL). Manifest total 2,400 parts.

### MFCAD++ — opt-in (not script-downloadable)

- Paper: Colligan, Robinson, Nolan, Hua, Cao, *Hierarchical CADNet: Learning from B-Reps for
  Machining Feature Recognition*, Computer-Aided Design 147 (2022) 103226.
- Landing / DOI: https://doi.org/10.17034/d1fec5a0-8c10-4630-b02e-b92dc81df823
  (https://pure.qub.ac.uk/en/datasets/mfcad-dataset-dataset-for-paper-hierarchical-cadnet-learning-from)
- Download: https://pure.qub.ac.uk/files/278385243/MFCAD_dataset.zip — 1,540 MB zip
  (DataCite record); behind a Cloudflare challenge for non-browser clients (probed: HTTP 403
  `cf-mitigated: challenge`, also from a real browser `fetch`). The Hugging Face mirror
  https://huggingface.co/datasets/AI4Manufacturing/mfcadpp is gated (`gated: manual` — access
  needs the owners' approval), so it is no scripted alternative either. Obtain the zip once by
  hand and pass `--archive`.
- Size: 59,665 STEP (train 41,766 / val 8,950 / test 8,949 per the landing page; we re-split by
  sha1(part_id), contract §4).
- Format / labels: STEP AP214 written by pythonOCC; the class index of every face is stored as
  its `ADVANCED_FACE` name (generator README: https://gitlab.com/CAPP-SRC/mfcad2-dataset).
  25 classes = `feat_names` in the generator's `Utils/parameters.py`. No instance labels —
  instances are connected same-family faces (contract §6), so two touching features of the same
  family merge.
- Licence: **CC BY 4.0** (landing page "Licence: CC BY"; DataCite rightsList
  `cc-by-4.0`, https://creativecommons.org/licenses/by/4.0/legalcode). Commercial use allowed;
  obligation: attribute (cite the paper, name the dataset, link the licence, state changes).
- CANON: contract §3.1 — full coverage of hole/passage/slot/step/pocket/o_ring/fillet/chamfer/
  stock; through/blind comes from the class itself.
- Caveats: synthetic prismatic stock (one block, 5–14 features), single body.

### mfcadpp_gen (our port of the MFCAD++ generator) — recommended (default)

- Why: MFCAD is all planar; MFCAD++ adds the curved classes (holes, O-rings, rounds, circular
  slots/steps/pockets) but its zip is not script-downloadable. Its generator is MIT, so we run it.
- Generator: https://gitlab.com/CAPP-SRC/mfcad2-dataset (MIT, © 2025 Andrew Colligan; commit
  `c171b76bb6f7e2537fcfafe6324b64a07d5e98db`, fetched as the GitLab archive; mirror
  https://github.com/josephkwok986/mfcad2), ported from pythonocc-core + numba to OCP + numpy in
  `mfcadpp_gen/` (licence + attribution in `mfcadpp_gen/LICENSE`, changes listed in its
  `__init__.py`). Same 24 features + stock, same bound search / depth rules / sketches, same
  per-face labelling through the modelling history (`Modified`/`IsDeleted`).
- Run: `build_manifest` generates missing seeds itself (`--mfcadpp-gen-count/-seed/-dir/-workers`)
  or `python -m training.viewpoint.datasets.mfcadpp_gen --count N --workers W` does it alone.
  Each seed is deterministic (`random.Random(seed)`; the same seed gives the same sidecar across
  runs and processes). Parts are generated in worker processes so an OCC crash or hang (600 s)
  costs one seed (`<seed>.failed.json`), not the run; finished seeds are reused.
- Files (`$CHUDWARE_VIEWNET_DATA/raw/mfcadpp_gen/`): `<seed>.step` with every face named by its
  face id, `<seed>.labels.json` with class, instance and geometry per face id — contract §8.
- Labels: class per face from the generator (§3.1 table → CANON); instances are the generator's,
  so touching features of one family stay apart; through/blind from the class.
- Licence: generator MIT (keep the notice); the parts are generated by us — no third-party data.
- Measured build (2026-09-28, `--sources mfcad,gsl,mfcadpp_gen --limit 1500 --gsl-count 150
  --mfcadpp-gen-count 3000 --mfcadpp-gen-workers 10`, 12-core machine): 24 min 5 s wall, of which
  generation 1,214 s (≈ 4 s per part per worker, 10 workers); 3,000/3,000 seeds produced a
  valid solid; 2,999 kept at match rate 1.0 (mean and min, 0 unmatched faces); 1 dropped by the
  sidecar guard (seed 876: one face read back 1 % smaller after the STEP round trip). Features:
  pocket 4,285, slot_through 3,251, step_blind 3,237, slot_blind 3,227, step_through 3,207,
  passage 3,136, fillet 1,122, chamfer 1,083, o_ring 1,078, hole_blind 1,056, hole_through 1,026.
  Curved-class faces: Oring 3,395, blind_hole 2,183, round 1,313, circular_through_slot 1,384,
  through_hole 1,195, circular_end_pocket 5,255, circular_blind_step 2,309, v/h circular-end
  blind slots 4,734 / 4,202. Splits 2,384 / 315 / 300. Manifest total 5,399 parts (MFCAD 1,500,
  GSL 900, mfcadpp_gen 2,999; all splits 4,290 / 561 / 548).

### GSL (our engine-generated families) — recommended (secondary)

- Generator: `tools/gsl_dataset_gen.py` (7 families: plate_bolt_circle, pocketed_block,
  turned_shaft, ribbed_bracket, shelled_enclosure, bladed_disk, swept_pipe).
- Labels: the engine's own `owner_map` (feature that created each face), mapped by contract
  §3.3; extrude/revolve side vs end from the profile-sketch normal / datum axis; holes measured
  through/blind per instance. Each sample is exported to STEP and re-imported through the same
  `import_file` path as every other source, so ordinals mean the same thing everywhere.
- Licence: generated by Chudware — no third-party rights.
- Probe (2 seeds × 7 families): 12/14 kept at match rate 1.0; `swept_pipe` drops at 0.80 because
  its elbow face reports 162.9 mm² on the live document and 488.6 mm² after STEP re-import
  (the 98 % rule catches it; not relabelled).
- Join fix (2026-09-28): the generator joined owner_map on `(last body, hint_index+1)`;
  doc_query's `hint_index` runs across every body, so any multi-body sample got body 1's faces
  labelled with the last body's owners (probe: box + separate cylinder → box faces read
  "cylinder" / "import_or_base"). It now joins on the engine-stamped `body`/`topo` keys.

### NIST best-view benchmark (Dutagaci, Cheung, Godil 2010) — sanity check

- Paper: *A benchmark for best view selection of 3D objects*, ACM 3DOR 2010,
  https://doi.org/10.1145/1877808.1877819.
- Landing: https://doi.org/10.18434/M32209 (catalog: https://catalog.data.gov/dataset/a-benchmark-for-automatic-best-view-selection-of-3d-objects)
- Download: https://data.nist.gov/od/ds/mds2-2209/3D_BestView.zip with published SHA-256
  https://data.nist.gov/od/ds/mds2-2209/3D_BestView.zip.sha256 (`fetch` verifies against it).
  data.nist.gov timed out (Cloudflare 524 / no response) on both probe attempts during this
  survey, so the archive size is not recorded; URLs are from the data.gov catalog entry.
- Content: 68 triangle meshes, best views picked by 26 subjects, view-selection-error code.
- Licence: https://www.nist.gov/open/license. NIST notes some meshes are "standard models"
  used across 3D research — those may carry their original owners' terms; use internally for
  evaluation, do not redistribute or train on the meshes.
- CANON: none (no face labels). Use: check that high-utility shots are not wildly off human
  preference; it is not the objective (VLM answer accuracy is).

### MFInstSeg (Wu, Lei, Peng, Gao 2024, AAGNet) — blocked on licence

- Paper: *AAGNet: A graph neural network towards multi-task machining feature recognition*,
  RCIM 86 (2024) 102661, https://doi.org/10.1016/j.rcim.2023.102661.
- Code (MIT): https://github.com/whjdark/AAGNet — includes the MFInstSeg generator
  (`dataset/main.py`, pythonocc-core 7.5.1).
- Download: Google Drive https://drive.google.com/file/d/1T2sHlL-4qlsXTxu3AMBB4h-N1I5VqNky
  (`data2.zip`, 1,801,353,969 bytes, probed; Range supported) or Baidu AI Studio.
- Layout (probed): `steps/<id>.step`, `labels/<id>.json` =
  `[[id, {"seg": {face: class}, "inst": NxN same-instance matrix, "bottom": {face: 0|1}}]]`,
  62,496 entries each; same 25-class table as MFCAD++.
- Licence: the repository licence covers the software; **no licence is stated for the data**.
  Default copyright applies → not used for shipped training (`fetch`/`build_manifest` need
  `--allow-unverified-license`). Clean alternative: run the MIT generator ourselves.
- CANON: contract §3.1; real instance ground truth (better than adjacency grouping).
- Probe: 3 parts through the full pipeline — match rate 1.0 on all three.

### Fusion 360 Gallery — rejected (non-commercial)

- Repo / docs: https://github.com/AutodeskAILab/Fusion360GalleryDataset
  (segmentation: `docs/segmentation.md`).
- Segmentation s2.0.1: 35,680 parts, 3.1 GB,
  https://fusion-360-gallery-dataset.s3.us-west-2.amazonaws.com/segmentation/s2.0.1/s2.0.1.zip;
  extended STEP: 42,912 STEP, 506,333,119 bytes (probed),
  https://fusion-360-gallery-dataset.s3.us-west-2.amazonaws.com/segmentation/s2.0.1/s2.0.1_extended_step.zip
  (layout probed: `breps/step/<id>.stp`, `breps/seg/<id>.seg`, `timeline_info/<id>.json`,
  `segment_names.json`). STEP files are scaled ×10 by the exporter.
- Reconstruction r1.0.1: 8,625 sequences, 2.0 GB.
- Labels: ExtrudeSide/End, CutSide/End, Fillet, Chamfer, RevolveSide/End per face → CANON
  one-to-one (contract §3.2).
- Licence: https://github.com/AutodeskAILab/Fusion360GalleryDataset/blob/master/LICENSE.md —
  clause 1 "only for non-commercial research purposes"; clause 11 binds a for-profit employer.
  **Not usable for Chudware training.** The reader exists for non-commercial research only and
  every tool refuses it without `--allow-noncommercial`.

### Text2CAD — rejected (non-commercial)

- https://huggingface.co/datasets/SadilKhan/Text2CAD — licence **CC BY-NC-SA 4.0**. Text prompts
  for DeepCAD models; no face labels. Excluded.

### ABC (Koch et al. 2019) — not for v1 labels

- Site: https://deep-geometry.github.io/abc-dataset/ (chunks of 10k models; md5 + sizes published).
- Licence: "The copyright of the CAD models is owned by their creators" — Onshape Terms of Use
  1.g.ii (https://www.onshape.com/en/legal/terms-of-use): Free-plan public documents created
  on/after 2018-08-07 (or earlier without a LICENSE tab) grant use/copy/modify/sell rights;
  older or paid-plan documents with a LICENSE tab may reserve more. A per-document filter on the
  ABC `meta` yml would be required.
- Labels: surface/curve patch types (`features` yml), no feature semantics → only `other`.

### DeepCAD (Wu, Xiao, Zheng 2021) — future op-label source

- https://github.com/rundiwu/DeepCAD (code MIT); data http://www.cs.columbia.edu/cg/deepcad/data.tar
  (208,074,561 bytes, probed).
- Sketch-and-extrude construction sequences parsed from Onshape public documents (ABC links) —
  same per-document Onshape terms as ABC. No face labels, but rebuilding a sequence in our
  engine would give exact op labels exactly like GSL. Needs the ABC licence filter first.

### CADTalk (Yuan et al., CVPR 2024) — rejected

- https://github.com/YYYYYHC/CADTalk (code MIT); data on Google Drive, licence not stated.
- Labels are semantic part names on OpenSCAD blocks (leg, seat, …), not geometric features —
  no CANON mapping.

### Secord, Lu, Finkelstein, Singh, Nealen 2011 — baseline idea only

- *Perceptual models of viewpoint preference*, ACM TOG 30(5),
  https://pixl.cs.princeton.edu/pubs/Secord_2011_PMO/index.php (paper, video, 85 MB demo zip).
- No data licence stated; not downloaded. Its fitted attribute model (projected area,
  silhouette length, …) informs `hand_utility`-style baselines; the study data is not used.

## Label mapping

Normative tables: `contracts/geom_labels.md` §3 (MFCAD++/MFInstSeg 25 → CANON, Fusion 8 → CANON,
GSL owner feature → CANON), §7 (MFCAD 16 → CANON) and §8 (mfcadpp_gen, the §3.1 table).
Correspondence to our engine is geometric (surface type + centroid + area), never by face order;
parts below 98 % matched faces are dropped and listed in `geomlabel.reports.jsonl`.
