# work/ — git-tracked task board

Solo, file-based task tracking: every card is a markdown file in git, no external
tracker. **`work/WORKFLOW.md` is the normative policy** (status/priority/lane/kind
vocabulary, the completed-task archive, the deferred-plans registry, the MCP freshness
and derived-asset rules, GUI ownership). This README only covers layout, the card
schema and the CLI. Where the two disagree, WORKFLOW.md wins.

There is no claim step, foreman, worktree or team-coordination layer. Pick a card,
do it, mark it.

## Layout

```
work/
  WORKFLOW.md      board policy (normative)
  DAG.md           generated by `work.py dag`; never edit by hand
  tasks/           live task cards, one file per card
  tasks/done/      archived terminal cards (status done | dropped)
  backlog/         live backlog cards (T-BL*), same schema
  backlog/done/    archived terminal backlog cards
  questions/       open per-task design questions (see questions/README.md);
                   answered ones move to questions/archive/
  context/         section context packs read by the /ctx-* skills
  audits/          dated subsystem audit reports
  prompts/         driver.md (template used by `work.py prompt`) and dated,
                   historical handoff prompts
  tools/           work.py (board CLI, stdlib only), issue_reporter.py
  report.sh|.bat   launch tools/issue_reporter.py (bug/idea -> GitHub issue + backlog card)
```

`sync.sh`/`sync.bat` call `work/tools/teamsync.py`, which no longer exists (the
team-sync layer was retired), so they do not run.

`work.py` loads `tasks/`, `backlog/` and both `done/` folders. Live cards depend on
archived ones, and readiness needs those statuses, so moving a card into `done/`
changes layout only, never command output.

## Lifecycle

Statuses (validated by `work.py`): `todo`, `doing`, `review`, `done`, `blocked`,
`backlog`, `dropped`.

- `todo` → `doing` → `review` → `done`; `blocked` when stuck on something outside
  the card; `backlog` for shelved-but-wanted work.
- `dropped`: cancelled or superseded, never coming back. Say why in the card body.
- `deferred: yes` parks a card inside a parked plan; it disappears from `ready` until
  un-parked.
- A card is `done` only when every Definition-of-done box is honestly checked and the
  relevant gate (`scripts/gate.sh` for core/engine/agent work, `./build.sh` at minimum)
  is green. Boxes needing live/manual verification stay unchecked until someone has
  actually done that check.
- When a card becomes `done` or `dropped`, move it into the matching `done/` folder.

After status or dependency changes, regenerate `work/DAG.md` with `work.py dag`. Never
edit it by hand.

## Card schema

Flat front matter: `key: value` scalars and inline lists. Everything after `#` on a
front-matter line is a comment, so values cannot contain `#`.

```
---
id: T-X9                         # required; unique across live + archived cards
title: Short imperative title    # required
workstream: X                    # required; free-form grouping used by board/dag
owner: unassigned                # required; informational only (no claiming)
status: todo                     # required; one of the statuses above
branch: task/T-X9-short-slug     # required; must match task/<id>-<slug>
depends_on: [T-X8]               # required; ids must exist (cycles are rejected)
priority: 3                      # optional; int 1 (drop everything) .. 5 (default)
lane: parts-sourcing             # optional; see WORKFLOW.md §1 for the lane list
kind: fix                        # optional; fix | overhaul | new
deferred: yes                    # optional; yes | no
day: 3                           # optional; legacy sprint-day sort key
blocker: why it is blocked       # optional; free text, used with status: blocked
---
```

The work is on `master` (see the chudware-dev skill); `branch:` is a required naming
field, not an instruction to branch.

Usual body sections: Context, Files / areas touched, Steps, Definition of done
(checkbox list), AI hints, Progress log (dated entries). Run `work.py validate` after
editing front matter.

## CLI

Read-only (safe anywhere):

```
python3 work/tools/work.py validate                  # schema, branch names, deps, cycles
python3 work/tools/work.py ready [--include-deferred] # todo cards whose deps are all done
python3 work/tools/work.py board [--workstream W] [--status S] [--lane L] [--kind K] [--owner O] [--json]
python3 work/tools/work.py roadblocks [--json]       # review queue, blocked, open questions
python3 work/tools/work.py lanes [--json]            # per-lane ship-readiness rollup
python3 work/tools/work.py prompt ID                 # prompts/driver.md + the card, as a work order
python3 work/tools/work.py dag                       # rewrite work/DAG.md
```

`work.py set ID [--priority N] [--lane L] [--kind K] [--deferred yes|no] [--reason "..."]`
edits card metadata and then **commits and pushes that card to `master` itself**. It
needs `--owner NAME`, because the identity helper it would otherwise read is not
present.

`claim`, `note`, `status`, `release`, `relink`, `checkdod`, `mine`, `whoami`,
`assignments` and `assign-lane` belong to the retired multi-contributor workflow.
`claim`, `note`, `status`, `release`, `relink`, `checkdod` and `assign-lane` commit and
push on their own, and most of them enforce card ownership. `whoami` needs the removed
identity helper. The solo workflow uses none of these: edit the card file directly.
`prompts/driver.md` still contains that era's claim and worktree setup steps, so skip
those when you use `prompt`.
