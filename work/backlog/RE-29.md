## Context
Reverse Engineering must reach Reconstruct/Model from MORE than the photo Capture→Scale
lane. This task builds the **web/part-number research lane**: given a part number, a search
query, or a vendor/listing URL (no local files, no photos), pull the datasheet + specs +
images from the internet into the session and feed the existing `reveng_datasheet.json`
mission (n_ingest → n_mpn_fastpath → n_datasheet_read → n_dim_gate → n_build → deliver).
This is the backbone of the Parts Library "make an un-modeled part" flow (see RE-23/RE-30).

Reuse existing seams — do NOT reinvent: `research_web_search`, `research_datasheet_fetch`,
`research_fetch_page` (services/mcp/research_tools.py), `match_part_number`/`spec_sheet_match`
(services/mcp/spec_tools.py + engine_oracle/spec_sheet_matcher.py), the browser acquisition
service (services/browser adapters) for authenticated vendor pages/PDFs/images, and RE-15's
`engine_oracle/vision/datasheet_ingest.py`. Land the assembled bundle in the session
`datasheet/` dir per contracts/reveng.md (aicad.reveng_session/1).

## Write-set
- `engine_oracle/vision/research_ingest.py` (new) — orchestrates query/part#/URL → spec bundle
- `services/mcp/reveng_tools.py` (additive at RE-ANCHOR) — new tool `reveng_research_source(session_id, query?, part_number?, url?)` returning the assembled bundle + candidate MPNs/dims; and let `reveng_start_session` accept a `research` seed
- `services/mcp/test_reveng_research_ingest.py` (new)

## Acceptance
- `python3 -m pytest services/mcp/test_reveng_research_ingest.py -q` passes: with the network/
  research + browser tools MOCKED, `reveng_research_source` assembles a datasheet bundle into the
  session `datasheet/` dir, extracts candidate part number + dims, and the result can launch the
  `reveng_datasheet` mission (mock node runners). With tools unavailable/offline it returns the
  honest `{"ok": false, "reason": "backend_not_provisioned"|"offline", "hint": ...}` envelope —
  never a traceback.
- Existing `services/mcp/test_reveng_tools.py` + `test_mcp_freshness.py` still pass.
- No fabricated specs: every pulled dimension carries provenance (`datasheet`/`web`/`vendor`) and
  fit-critical dims still route through `confirm_dimensions` (intake ledger).
