**Context (HOT-SPOT):** the groundedness checker under `tools/translator/` is shared
T-H4 ∩ T-F10, one implementation, two callers. T-H4 (sonnet-tomo, in flight) OWNS the
implementation; T-F10 defines the seam its eval harness consumes. I did NOT implement a
checker — I wrote the interface + a clearly-marked minimal stub
(`tools/translator/groundedness.py`, `# SEAM(T-H4)`).

**The interface I froze (my recommendation for T-H4 to implement against):**

```python
@dataclass(frozen=True)
class Verdict:
    value: float            # the numeral, unit-normalised
    unit: str               # canonical gsl-ser/v1 unit ("mm","MPa","pct","count",...)
    grounded: bool          # True iff supported by some slot of `state`
    matched_path: str | None  # the slot path it grounds to, if grounded

class GroundednessChecker(Protocol):
    def check(self, text: str, state: dict) -> list[Verdict]: ...

# module surface the harness calls:
groundedness.check(text, state) -> list[Verdict]
groundedness.set_checker(checker)   # T-H4 installs the real impl here
groundedness.get_checker(); groundedness.is_stub()
```

- `state` is the gsl-ser/v1 **state dict** (the `_digest`-shaped payload;
  `tools/translator/gsl_ser.py:enumerate_slots` is the canonical slot source). T-H4's
  checker can call `enumerate_slots(state)` to get the ground-truth slots.
- One `Verdict` per numeral found in `text` (use `gsl_ser.extract_numerals` for a
  shared, sid-safe numeral tokenizer — it already strips identifier digits like `f7`
  and version tags).
- The T-F10 slot-fidelity metric is INDEPENDENT of this seam for its primary SER score;
  it consults the checker ONLY to attribute EXTRINSIC (invented-feature) hallucination.
  So T-H4 can land the richer checker without touching the harness — `set_checker()`
  swaps it in, `is_stub()` flips to False, the residual report re-labels itself.

**My recommendation:** T-H4 implements `GroundednessChecker.check` with the same
signature and installs it via `set_checker()`. The stub (`_MembershipStub`) is exact
slot-membership only — the FLOOR of groundedness; T-H4 adds unit-sanity ranges,
tolerance-stack awareness, and the IP-7 inference output-gate semantics. Please do NOT
grow the stub into the real checker; extend T-H4's module and register it.

**Open sub-question for T-H4/advisor:** should `Verdict` also carry an
`intrinsic_vs_extrinsic` tag, or is that the harness's job? I kept it the harness's job
(intrinsic = wrong value for a slot the caption *labels*; extrinsic = numeral matching
no slot at all), because intrinsic requires the label-alignment the slot scorer already
does and the standalone checker only sees free text. If T-H4 wants the checker to own
both, say so and I'll route extrinsic-only from it.
