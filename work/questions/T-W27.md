## 1. Execution-reality blocker (BLOCKS a real cycle) — needs the lead / infra

Cycle-1 ran in **MOCK mode**. A genuine model-in-the-loop cycle is not runnable in this
environment because THREE independent seams are missing:

- **No real tool-executing `agent_fn`.** `services/dag/node_runner._default_agent_fn`
  imports `services.agent.providers.anthropic.AnthropicProvider`, but the module is
  `anthropic_provider` (class `AnthropicProvider`). The import fails and the node runner
  silently falls back to `_StubAgentResult` (always `stop_reason="confirmed"`,
  `success=True`). So even "live" DAG nodes are stubs. → **Fix the import in
  node_runner.py** (`from services.agent.providers.anthropic_provider import
  AnthropicProvider`), and give it a real tool-execution loop (it currently calls
  `loop.run`, the single-part code-extraction loop, not a role turn that executes MCP
  tool calls against the core). This is the single highest-leverage wiring gap for the
  whole Pillar 20 eval story.
- **No provisioned model.** `~/.local/share/Chudware/models/` has only a `qwen3vl4b/` dir,
  no `*.gguf`; no frontier API key in env. Provision the T-W26 bundled qwen3-4b (or set a
  frontier key) to run a real cycle.
- **No C++ core** (`core_bridge.available() == False`), so real geometry AC checks
  (`verify_battery`, `fit_report`, `cam_simulate`, `run_fea_*`) cannot recompute. The gym
  grades against ledger-recorded values in mock mode; a real cycle needs the `.so`.

The gym's `execution_probe()` reports all three honestly and stamps every report + every
telemetry record `mode: mock` / `training_usable: false`.

## 2. Pipeline verify gate is structurally fabricated (design note)

`loop._phase_gate_context` hardcodes `{ac: "PASS"}` for every criterion in the VERIFY
phase — the mission's own verdict is derived from node COMPLETION, not from reviewer
results in the ledger. This is why the gym is an INDEPENDENT grader (it never trusts the
pipeline PASS floor). When a real reviewer node lands, it should write per-criterion
results into the ledger and the gate should read them; until then, any "mission done" is
a structural floor, not a verified verdict. Not fixed here (loop.py is read-only per the
driver notes) — flagged for the lead.

"the classifier detects these classes", not "the model exhibits them at this rate"):

  FIRST; suppress cosmetic questions." Evidence: C4/seed2 asked "what color?" while the
  blocking `pin material / process` ambiguity went unclarified.

  THAT tool." Evidence: C1/s2, C4/s3, C5/s3 verified a criterion with `measure_part`

  `replan_request`; do not silently proceed." Evidence: C2/s2 proceeded past the

in-report; these prompt levers are not.
