# T-W31 — questions for the advisor

## Q1: --parallel 8 default vs per-slot context budget (filed 2026-07-05, fable-reef)

**Context.** W29's recommendation ("Enable `--parallel 8` on the bundled server;
there is VRAM headroom", REPORT.md L180) is now the shipped CUDA default in
`installer/llamacpp.py ensure_server_running()` (only when the user pins neither
`parallel` nor `ctx_size` — explicit cfg always wins). The integrator smoke
(-ngl 99 -np 8 -c 32768) is the exact shipped configuration.

**Finding from the gym C1 re-run (cycle-1-real-r4-cuda).** With -np 8 -c 32768,
b9860 gives each slot n_ctx = 4096 (kv split across slots; confirmed live via
/props `default_generation_settings.n_ctx`). The local-24k tier profile budgets
23900 tokens per turn — nearly 6x the per-slot window. The r4-cuda run graded
0.000 (same as baseline) but fired a NEW `context_loss` classification that r3
did not, consistent with the squeeze.

**Recommended answer (my preference).** Keep --parallel 8 for fan-out workloads
but raise the default `-c` so per-slot ctx matches the local-24k budget:
`ctx_size = 24576 * parallel` would want 196k KV — likely too much VRAM for
qwen3-4b at 12 GB. A middle course: default `-c 131072` (16k/slot) if KV fits,
else fall back to -np 4 -c 98304 (24k/slot). Needs a measured VRAM check per
model before changing the default; W29 only proved -np 8 -c 32768.

**Alternatives.**
1. Leave the shipped default as-is (matches the only verified smoke) and let
   W32's turn path request a serial server (`parallel=1, ctx_size=24576`) for
   deep-think roles while fan-out uses the -np 8 pool. (Cleanest split, matches
   the W29 role-shape table's two token-spend shapes.)
2. Auto-derive ctx_size from tier budget x parallel with a VRAM guard.

Not blocking: the default only applies when the caller sets nothing; the gym /
mission pipeline can pass explicit cfg today.

## A1 (foreman, 2026-07-05)

**Go with Alternative 1 — role-shape server split.** Ship stays as-is (-np 8
-c 32768 is the only measured config); W32/W33's turn path requests servers by
role shape via the new `model_for_role_shape()` seam:
- fan-out workers (qwen3 prompted-JSON): the -np 8 pool, 4k/slot is FINE for
  short directive turns — that is what fan-out means;
- deep roles (planner/reviewer, anything holding the source-of-truth context):
  a dedicated `parallel=1..2, ctx_size=24576` instance. Two instances of the
  same weights are acceptable if measured VRAM fits (weights dedupe is not a
  thing across processes — MEASURE, don't assume; the r4 run held 7995/12288
  MiB with ONE np8 server, so budget the second instance's weights + KV before
  defaulting it on; degrade to serial-only when it doesn't fit).

This is also the direct implementation of Hunter's original directive: "as many
helpers as many thought paths ... while still keeping the source(s) of truth in
there somewhere protected" — breadth on the slot pool, protected depth on the
full-context instance. Do NOT auto-derive ctx from tier budget (option 2) — it
changes the verified default silently and the VRAM guard would be guessing.
Cut the implementation into T-W32's dispatcher work or a small T-W33 if W32 is
already deep; the seams (structured_output_for/model_for_role_shape) are ready.
