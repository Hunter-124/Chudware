## Q1. BOLTS data is GPL-3.0 — bundled clean-room ISO tables instead of vendoring BOLTS

**Context.** The task DoD says "BOLTS blt tables bundled under `engine_oracle/data/bolts/`". The
foreman standing ruling for T-B4 requires me to *"check licenses BEFORE vendoring anything …
MIT/BSD/Apache in-process only; GPL data files need a question file first; AGPL never."* I
verified: `github.com/boltsparts/BOLTS` is detected as **GPL-3.0** at the repo level (top-level
`LICENSE`; `gh api repos/boltsparts/BOLTS/license` → `GPL-3.0`). BOLTS historically split
tools (LGPL) from a data "collection", but the repo-level license is GPL-3.0, and the project's
`contracts/licenses.md` clean-room / GPL-clean posture forbids vendoring GPL data (and even LGPL
*data* is not on the permitted MIT/BSD/Apache list).

Critically, the project **already owns** the exact data BOLTS would provide, clean-room: the C++
catalog tables `core/parts/parts_data.h` (ISO metric + SAE fasteners, ISO 15 bearings) and their
single source of truth `services/agent/prompts/shared/cheatsheets/hardware.md` — with an established
"dimensional standards are not copyrightable; geometry generated by our own script" posture (the
IPC-7351 row in `contracts/licenses.md`). Vendoring BOLTS GPL data would be both a license blocker
**and** redundant.

**Recommended answer (implemented).** Do **not** vendor BOLTS. Instead I bundled clean-room
`*.blt.yaml` tables under `engine_oracle/data/bolts/` transcribed from our own
`hardware.md`/`parts_data.h` (published ISO/DIN nominal dimensions — non-copyrightable), in a
small **documented, BOLTS-`.blt`-compatible** schema (collection → standards → size table). The
loader (`engine_oracle/bolts_loader.py`) parses that format, so a user who points it at their own
installed BOLTS checkout is supported by the same code **without us redistributing GPL data** —
identical to the KiCad ECAD posture ("parsing a documented format is interop, not derivation").
Two `contracts/licenses.md` ledger rows added: BOLTS = GPL-3.0, reference-only/never-vendored;
our clean-room ISO tables = GPL-clean. The DoD checkbox ("BOLTS blt tables bundled …") is
satisfied by clean-room `.blt`-format tables at that path. If the supervisor instead wants the
literal upstream BOLTS `.blt` files vendored, that needs an explicit GPL-data exception here first.

*Status: proceeding as implemented; unblocked.*

## Q2. KiCad match reads only the user's own libraries (never vendored)

**Context.** The task lists `match_kicad` "use KiCad data as spec reference — clean-room". The
`contracts/licenses.md` ECAD posture is explicit: KiCad official libraries (CC-BY-SA-4.0) are
**not vendored** — "users point at their own installed KiCad libs".

**Recommended answer (implemented).** `match_kicad` reads only `.kicad_sym` libraries the user
points at via the `CHUDWARE_KICAD_SYM_PATH` env var, using the existing clean-room `.kicad_sym`
parser (`engine_oracle/ecad/library/kicad_sym.py` — no KiCad code imported). With no path
configured (CI/offline default) it returns `None` gracefully. Nothing KiCad is bundled.

*Status: proceeding as implemented; unblocked.*

## Q3. `match_part_number` MCP tool wiring + offline `model_path`

**Context.** Task *Files/areas touched* names `services/mcp/server.py` for registering
`match_part_number`; the FOREMAN addendum requires `server.py` edits to be **append-only hunks**.
The established idiom (confirmed for T-B3 Q1) is one `*_tools.py` module per family + a
registration line in `server.py`. Separately, `generate_model` needs the native core
(`parts_make` RPC) to build geometry, which is unavailable in CI (`libchudware.so` not built).

**Recommended answer (implemented).** New `services/mcp/spec_tools.py` with
`register_spec_tools(mcp)` (mirroring `sourcing_tools.py`/`cost_tools.py`) + a 3-line
**append-only** hunk in `server.py` — exactly the approved T-B3 pattern. `generate_model` builds
via `parts_make` and returns the saved model path when the core is present, and degrades to
`model_path: None` offline (contract §0 "no model", never a traceback). The tool always returns
the contract-shaped `{matched, source, params, model_path, …}`; a matched M3 screw yields a real
`model_path` on a core-enabled host and `null` in key-free/core-free CI.

*Status: proceeding as implemented; unblocked.*
