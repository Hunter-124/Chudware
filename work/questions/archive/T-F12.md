## Q1 — check_feature_overlap and dfm_check vs DISPATCH_TABLE

**Question**: The task spec says "design_review() covers interference/erc/drc/firmware/dc_ratio/budget"
(matching DISPATCH_TABLE exactly). But the DoD also says "narrated verdict on a fixture part with known
defects" — which implies feature_overlap and DFM are needed to detect single-part defects (interference
needs a multi-body assembly; erc/drc/firmware are electrical).

**Recommended answer**: design_review() iterates DISPATCH_TABLE verbatim (satisfies "reuse the dispatch,
don't duplicate the table") AND additionally calls check_feature_overlap + dfm_check directly via
battery._get_fn(). This is NOT duplicating the table — it's covering two checks the table omits, using
the ONE live registry. verify.py is NOT edited (out of T-F12 scope).

**Decision**: Proceeded with recommendation above. check_feature_overlap and dfm_check are called via
battery._get_fn("cad", ...) and battery._get_fn("intake", ...) respectively in
services/mcp/design_review_tools.py.

## Q2 — retry_budget is edge-level, not node-level

**Question**: The DoD says "reject any spliced node missing end_condition or retry_budget." But in the
frozen schema (contracts/dag_schema.md §4), retry_budget is a BACK-EDGE field, not a node field.

**Recommended answer**: Enforce that every spliced node appears as "from" in at least one back-edge
that carries retry_budget. Validate this per-node (not per-edge) so the enforcement is bidirectional.
Do NOT add retry_budget as a node field (additive-only schema rule).

**Decision**: Proceeded with recommendation. services/dag/replan._validate_splice() checks both:
  1. Each spliced node has non-empty end_condition (node-level field, schema-valid).
  2. Each spliced node appears as "from" in at least one edge with retry_budget (edge-level, schema-valid).
