## Q1 — Copilot-inline artifact card vs the agent_panel.cpp hot-spot (non-blocking)

**Context.** DoD bullet 1 wants the artifact card to appear *inline in the Copilot message
stream* ("card appears in Copilot with page-1 thumbnail; click opens preview; open-externally").
The Copilot stream is rendered by `ui/imgui/src/ui/agent_panel.cpp` — the supervisor-designated
hot-spot with TWO unmerged review branches sitting on it (T-F3 ask_dialog wiring, T-H1 telemetry).
Rendering a card inline requires: a `BlockKind::Artifact` enum value (app_state.h — fine), a
`case` in `agent_panel.cpp`'s `drawBlock` switch, a `drawArtifactCard` call site there, and a push
site in `app_state.cpp tickDemoAgent` to parse artifact paths out of the agent result. The
agent_panel.cpp footprint (switch case + call) is small but is a *content* edit to the hot-spot,
not a ≤3-line append — it changes the block-dispatch switch two other branches also touch.

**Decision taken (build unblocked meanwhile).** Built the preview pane + artifact cards as a fully
STANDALONE panel (`preview_pane.*`, `artifact_cards.*`) that lists every agent-produced artifact as
a card (page-1 thumbnail, Open-externally, Regenerate, Preview) and previews pdf/docx/pptx/xlsx/csv/
images — satisfying the card + file-explorer + async DoD bullets with agent_panel.cpp UNTOUCHED.
The literal *inline-in-the-bubble* rendering is left to the T-G7 copilot/panels wave that ports the
same view-model, so the two in-flight agent_panel branches merge without conflict.

**Recommended answer:** ACCEPT the standalone-only surface for T-F16; the inline-bubble card lands
in T-G7 (it reuses `drawArtifactCard` + `chudware::ui::ArtifactCard` unchanged — a `BlockKind::Artifact`
case is then a clean append once T-F3/T-H1 have merged). Alternative if inline is required now: I
add the switch case in a single isolated commit and flag the conflict risk. Defaulting to the
standalone surface unless told otherwise.

## Q2 — "Regenerate" semantics on an artifact card (non-blocking)

**Context.** The master plan says each card offers "regenerate". Regenerating the *underlying file*
means re-running the agent's `make_*` from the persisted `spec_ref` — an agent/tool action, not a
presentation-surface capability, and not a `deliverables/1` tool. render_document only previews.

**Decision taken / recommended answer:** In the pane, **Regenerate = refresh the preview** (evict
the cached page textures + re-call `render_document`), which is the honest presentation-surface
action (picks up a file edited on disk). Regenerating the artifact itself stays agent-driven
(re-issue the make_* with the saved spec) and is out of this pane's scope. ACCEPT unless a
spec-driven rebuild tool is wanted — that would be a new deliverables tool (contract change).
