## Context

Pillar 15 templates: the standard documents a professional engineer is expected to
produce, generated from live project state — numbers pulled from the engine, never
typed by the model. READ `docs/AI_TOOLING_MASTER_PLAN.md` §Pillar 15. Absorbs the
manual-generation half of backlog T-BL10/T-BL11 (compliance checklists stay in T-BL11).

## Files / areas touched

- `services/deliverables/templates/` — the five v1 templates
- `services/deliverables/joins.py` — provenance joins to describe_* / FEA results /
  BOM+cost rollups / CAM setup sheets / drawing exports
- `services/mcp/` — template-specific spec schemas surfaced via cad_guide

## Steps

1. **Design-review deck** (pptx): rendered views/contact sheets, mass properties,
   FEA margins, open risks/questions from the run record.
2. **Calc package** (docx→pdf): equations, assumptions, material data with citations
   (Pillar 8 answer contract fields shown: source + fetched_ts), results tables.
3. **BOM/cost workbook** (xlsx): live formulas (qty × unit cost rollups), one sheet per
   assembly level, sourced-part links (WS-B data when present; graceful without).
4. **Test/verification report** (docx/pdf): requirements → evidence mapping (T-BL09
   schema when it lands; free-form criteria section until then).
5. **Assembly instructions + user manual** (md→pdf): exploded/step renders via existing
   render tools, torque/fastener callouts from the assembly data.
6. Each template: golden-file test against a fixture project; every numeral in output
   asserted equal to its engine-source value.
