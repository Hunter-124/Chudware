## Context

Pillar 14's mission-control UX (user-mandated 2026-07-02): the agent is a glass box.
The app streams the plan, current node, and every thought/action/tool call in real
time, and the user can steer AT ANY TIME without killing the run. This is also where
autonomy balance becomes concrete UI: the dial (T-A3), proposed-decision approvals
(T-F3), and the design-brief flow. READ `docs/AI_TOOLING_MASTER_PLAN.md` §Pillar 14
"Mission-control UX".

**GUI-placement rule:** view-model in `ui/abstract/`; minimal host wiring (the existing
`activity_panel` / agent-step stream is the seed); the ui/imgui migration ports it.

## Files / areas touched

- `ui/abstract/` — mission-control view-model (run tree, live event stream, steering
  commands)
- `host/src/ui/activity_panel.cpp` — upgrade: DAG run view (from `describe_project` /
  `dag_status`), streaming thought/action/tool-call rows, artifact links
- `services/dag/` — event stream tap (checkpointed events → UI), steering entry points:
  pause (T-A3 interrupt), inject-instruction, autonomy-dial change mid-run
- `services/agent/` — the built-in (non-DAG) agent loop emits the same event schema so
  one panel serves both

## Steps

1. Freeze the event schema (append to `contracts/interaction.md` or a small
   `contracts/agent_events.md`): plan snapshot, node start/finish, thought, tool call
   (name + args digest + result digest), question raised, artifact produced.
2. Wire the DAG executor and the built-in loop to emit it; persist with the checkpoint
   so a reopened app replays state.
3. UI: run tree with live status; event stream with thoughts visible (collapsible);
   steering controls — pause/resume, answer open questions inline (T-F3 dialog),
   inject an instruction at the next node boundary, per-run + per-node autonomy dial.
4. **Design-brief flow:** for a new mission, the agent's first visible output is an
   editable design brief (goals, constraints, design criteria, assumptions — T-BL09
   requirements schema when available) raised via ask_user `approval`; verify nodes
   reference it; deviations surface as "off-track" suggestions with evidence.
5. Live test: run a demo mission, steer it mid-run (pause → edit brief → resume),
   verify the trail shows everything.
