## Grep-sweep residue (all deliberate — T-G10 sonnet-elm)

Every remaining "AI-CAD"/"AI_CAD"/"ai-cad" hit falls in one of these intentional buckets:

1. **`AI_CAD_*` env var SET sites + read sites (~56 files)** — deliberately unchanged
   (Decision 2, work/questions/T-G10.md): `SHOPCRAFT_*` are canonical NEW names, honored
   via read shims (core_bridge `_env()`, gate.sh export shims, ui/imgui main.cpp
   `propagateShopcraftEnv()`); the `AI_CAD_*` names remain the internal transport so no
   harness/test/script breaks. Verified working under BOTH names (byte-identical shots).
2. **`ai-cad` in installer files (3)** — the `SERVER_NAME_LEGACY` compat constants and
   their docs; removed only on explicit `--unregister`.
3. **`AI-CAD2` binary/target name (~10 files)** — intentionally retained (Decision 3,
   additive alias): `ShopCraft` symlink/copy ships next to it; both launch.
4. **`host/` tree** — dies un-renamed by design (task Context).
5. **`libaicad` / `aicad_*` symbols, `dist/AI-CAD` stage dir** — engine ABI names and the
   Windows stage layout; out of scope for a GUI/ecosystem rename (would break the C ABI).
6. **History docs (`docs/`, `work/`), memory notes** — historical record; left as-is.
7. **Appdata literal `AI-CAD` in paths code (Py+C++)** — that IS the compat shim
   (`APP_NAME_LEGACY`, alias rule in 4 mirrored path resolvers).
