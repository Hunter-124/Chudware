## Result log (opus-sky, 2026-07-02)

Root cause was NOT the issue's hypothesized mid-loop `DocMirror::newPart(worker)` deadlock
(`newPart` returns fine — tree/sketch complete in ~3 s worker-present). It was two shot-harness
control-flow defects (full analysis in work/questions/T-G13.md):

1. **Worker-absent spin (all 10 step machines).** Each gates its body on `st.workerStarted` and
   only Breaks (in `endFrame`) once its `xShotDone` is set; `captureFrameBudget()` is 999999 for
   every `isScenarioMode()` scenario, so the generic budget path never rescues them. With no
   Python worker provisioned (default on an unprovisioned Linux box, `workerStarted==false`), the
   body never runs → `endFrame` returns `Continue` forever → the `--shot` loop spins to the outer
   `timeout` (124, no PNG). This is the filed deadlock.
2. **cam (worker-present too).** No `wantCam` branch in `endFrame()` + 999999 budget → cam did its
   work (`cam-shot: ok=1`) but could never write a PNG, hanging even worker-present at 180 s.

**Fix (harness only, scenarios not redesigned):** ui/imgui/src/ui/scenarios.{cpp,h}
- Worker-absent backstop in `endFrame`: `if (isScenarioMode() && !workerStarted && frame>=12)`
  capture the chrome-only frame + Break. Deterministic, frame-1-ish; inert worker-present so it
  can NEVER pre-empt the long-running fea/flow sim waits (14400/5400 frames, only reached
  worker-present).
- cam: `endFrame` `wantCam` branch captures on `camShotDone`; cam body converted to a small
  settle-based one-shot (+`loadMesh`) so the plate renders before capture.

**Verification (offscreen, `xvfb-run`; NO visible windows — Erik at the machine):** full 22-name
battery ×2. Worker PRESENT (`AI_CAD_PYTHON=/usr/bin/python3`): 22/22 PASS with REAL content
(spot-checked m1/cam/sketch PNGs — real filleted-box geometry, feature tree, sketch ribbon +
"Fully Defined"). Worker ABSENT: 22/22 PASS, exit 0, ZERO 124 hangs (was 10 hangs pre-fix).
`--selftest` → save=1 open=1 features=3 OK. Build green.

**Note for downstream (T-G8/G9, T-G12):** the watchdog prevents hangs, but REAL screenshots need
the Python worker provisioned (`AI_CAD_PYTHON` / a venv) — worker-absent captures are chrome-only.
Deferred question in work/questions/T-G13.md: whether to add a shot-mode PATH-python3 fallback so
real captures are the default (my lean: yes, low-risk; left for advisor since it touches worker
startup globally). glassperf is not a step machine — just slow offscreen (~70 s); needs a >90 s
capture timeout, no code change.
