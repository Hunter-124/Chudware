## Verification log (opus-rime, 2026-07-03)

Root cause: the docked PM/popups are frosted glass over the always-light 3D viewport.
`adaptivePanel()` picks text tone from the LIVE backdrop luminance — over the light
viewport it picks DARK text. The bug: several surfaces filled their background with the
theme-static `pal.glassBg` (DARK in the dark theme) instead of the SAME adaptive
`surf.tint` the text reads against → dark text on dark fill (black-on-black), and
light-on-light when the tone flipped. Value widgets also used the theme-static
`pal.text`, washing out over the adaptive light fills.

Fixes (5 files, all in `host/src`):
- `ui/property_manager.cpp`: group-card `ChildBg` + floating-fallback `WindowBg` now use
  `surf.tint`; a global `ImGuiCol_Text = surf.textPrimary` push makes VALUE text adaptive
  too (strict no-op in the palette-fallback regime where `surf.textPrimary == pal.text`);
  `pmCompactLabel` truncates over-long labels with an ellipsis (+tooltip) so the field
  column never overlaps the label ("Tangent propagation"/"Reverse direction" cases).
- `ui/evaluate_dialogs.cpp`: mass/measure/section windows apply auto-fit height every
  frame (`ImGuiCond_Always`, y=0, width pinned 340) instead of `_Appearing` — they were
  frozen at their first-frame "Computing" size and clipped the readout.
- `ui_theme.cpp`: `ImGuiCol_Border` gets its own higher-contrast per-theme value so
  floating subwindows read a crisp outline (separators keep the softer `p.border`).
- Harness (separate commit): `app.cpp` `pmform` shot gains `AI_CAD_PMBOX=1` to load the
  box fixture so the PM samples a LIVE backdrop (the bug regime); `scenarios.cpp` evalmass
  settles ~40 frames so the async result populates and the window grows.

Screenshot evidence (dark + light each, eyeballed):
- PM Fillet form (pmform+PMBOX): labels+values readable, card contrasts, "Tangent prop…"
  truncates (no overlap). Before: dark-on-dark / white-on-white in the group card.
- PM Extrude(Boss) form: Boss/Cut toggle, End Condition combo, Depth value all readable;
  "Reverse direc…" truncates.
- Evaluate Mass Properties: window auto-grows to show Volume/Mass/COM/Inertia/Principal
  axes; before it clipped to just the material combo.
- Settings modal: crisp visible border in both modes (was near-transparent in light).
- m1 / sketch feature-tree + toasts: readable, no black-on-black.

Tooltip regression (caught in advisor review, fixed): the value-text fix pushes
`ImGuiCol_Text = surf.textPrimary` as drawBody's default, which bled into the 12
`SetTooltip` calls in drawBody/pmCompactLabel — a tooltip is a separate popup on the
theme-toned dark `glassBg`, so dark adaptive text = black-on-black. Routed all PM tooltips
through `pmTooltip()` (re-pushes `pal.text`, mirroring the open-combo pattern). Hover
tooltips can't be captured by the headless shot harness, so this is confirmed by call-site
audit, not screenshot.

Note on findings #4 (Copilot-tab tooltips): plain `SetTooltip` tooltips render the theme
default text (near-white in dark) over the dark `glassBg` PopupBg = readable; the Copilot
header tooltips balance their text push/pop (verified by source audit). Audit-verified
rather than screenshot-verified (same headless-hover limitation) — flagging for Erik to
confirm on the round-2 walkthrough.

Known pre-existing (NOT in scope, flag for Erik): the Evaluate Material combo's OPEN
dropdown list draws `surf.textPrimary` on the theme dark popup — dark-on-dark while open
(same class, different owner: `evaluate_dialogs.cpp:189`). Left untouched.

## AI hints

- Fix the THEME, not the windows: one token table change should cascade. If you find
  yourself patching per-popup colors, you're at the wrong altitude.
- gui-overlay-design-decisions memory: glass style is a locked design intent — reuse
  the existing tooltip/Copilot glass helpers rather than re-inventing.
