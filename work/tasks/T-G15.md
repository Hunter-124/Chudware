## SHARED VISUAL CONTRACT (T-G15 icons <-> T-G16 ribbon glass) — decided opus-gleam 2026-07-03

This is the agreement Erik required BEFORE mass-generating icons, so the T-G16 ribbon
restyle and the T-G15 icon assets cannot diverge. Reuse the EXISTING glass helpers in
`host/src/ui_theme.{h,cpp}` verbatim — never fork them.

Canonical helpers (from the codebase, do not reinvent):
- v1 layered glass = `ui::glassBackground(dl, mn, mx, rounding=8)` — shadow/fill/shine/
  border/specular, driven by `palette.glass*` tokens. THIS is what tooltips use.
- v1 row pill = `ui::glassRowBackground(dl, mn, mx, rounding=4, ...)` — Copilot rows.
- v2 adaptive = `ui::adaptivePanel(id,rect,group)` + `ui::glassPanel(dl,rect,GlassLevel,
  rounding,surf)` — backdrop-frosted; Copilot pane + toasts.
- Theme is read via `ui::activeTheme` (`Theme::Dark`/`Light`) and `ui::palette`.

RIBBON (T-G16):
- Band/chrome: v1 `glassBackground`, rounding **8dp** (identical to the tooltip glass
  Erik named as the reference). NOT v2 `adaptivePanel` — the ribbon sits under the title
  bar and does not reliably overlap the live viewport backdrop, so v2 would fall back to
  v1 anyway; using v1 directly is deterministic and theme-correct in both modes.
- Button hover/active pills: v1 `glassRowBackground`, rounding **4dp**. Keep existing
  semantics: accent underline on the active tab, accentSoft+accent outline on armed tools.
- Hit-targets and layout metrics UNCHANGED — cosmetic restyle only.

ICON BACKGROUND + CORNER TREATMENT (the divergence-preventer):
1. Any icon tile corner radius = **4dp** — same rounding language as the hover pills.
2. Icons carry NO baked background plate; they render on a **transparent** background so
   the glass shows through in BOTH light and dark mode. One asset serves both themes.
   - Line-art glyphs: UNCHANGED — SDF `drawIconGlass` tints by palette role
     (text/accent/disabled). Single asset, both themes.
   - Photographic / screenshot icons (Features 3D-Body/Dress-up/Pattern/Multi-body/
     Curves; Sheet-Metal Create; Appearance Material+Display; Manufacture 2.5D/Holes/3D/
     Turning/Cutting) and material-preset icons: captured from the real app GL viewport
     (or CAM simulator for Manufacture) at 2x -> downscaled, part centered filling ~80%
     of the tile, MODIFIED faces emphasized with the existing selection-highlight color,
     exported as a **transparent-background rounded-square tile (radius 4dp, ~2px inset
     margin)**. Theme-neutral: one transparent asset works on glass in both modes. They
     enter the atlas as MULTI-COLOR RASTER (they do NOT qualify for SDF) with white-tint
     identity, matching the existing badge/swatch raster path.
   - NOT the `render_part` MCP annotated image (XYZ gizmo + face labels) — that is a debug
     render, never an icon. Icons come from the clean viewport / CAM sim capture.
3. Family framing: 32px logical cell, ~2px transparent inset, iso-ish camera, neutral
   studio lighting, no gizmo/labels — so the whole photographic set reads as one family.

VERIFY: glass is palette-driven and photographic icons are theme-neutral, so one atlas
pair covers both modes; every UI change is checked headless in AI_CAD_THEME=dark AND
=light and the PNG is actually LOOKED AT.
