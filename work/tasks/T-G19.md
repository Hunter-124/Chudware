### Fix 1 — extrude depth/draft double-display (P1 functional)
Root cause: `host/src/ui/viewport_panel.cpp` drew a "Fixed active-feature readout panel"
pinned top-right (anchored to the Copilot column edge via `overlayColumnEdge(1)`) that
mirrored the PM's dimension fields for EVERY feature with dim candidates. Removed that
block entirely — the PM form is the single source of truth for these values.

Audit — every readout that draws a feature dimension in the viewport (grep of
`pmFormatDim` / `dimCandidates` in viewport_panel.cpp):
- REMOVED: the persistent top-right "Active Feature" panel (was the double-display). It
  was generic over `dimCandidates(activeFid)`, so it duplicated the PM for ALL feature
  types that expose dims — extrude (Depth + Draft angle — the exact case Erik reported),
  revolve, sweep, loft, shell, draft, fillet, chamfer, hole, rib, etc. Removing the one
  block fixes every feature at once.
- KEPT (not duplicates — live interaction feedback, follows the cursor only WHILE
  dragging): the push-pull face-drag chip (`s_pp`) and the Instant3D dim-handle drag chip
  ("Depth 25.0 -> 31.5 mm", `s_dim`), plus the on-canvas draggable dim handles/arrows.
- NOT a dimension (left alone): the top-right "Face N of Body" pick readout.

Extrude regression: the removed panel's rows came from `dimCandidates` for the extrude
feature = Depth + Draft angle — precisely the two values Erik saw twice. Gone.

### Fix 2 — OK/Cancel redesign + relocation
- Removed the OK/Cancel buttons from the in-PM glass header strip
  (`property_manager.cpp`); kept the keyboard Enter/Esc -> commit()/cancelEdits() path.
- Added `PropertyManager::drawChromeButtons(st, rightX, centerY)` — the PM owns commit/
  cancel + the form-ready guard; renders wider (40dp vs old 26dp) OK/Cancel buttons.
- `layout.cpp`: shrank the left-pane tab strip to fit only its 3 tabs and call
  `drawChromeButtons` in the freed top-row span — right-aligned just left of the collapse
  chevron, i.e. "above the PM, between the configurations and the collapse button."
- Icons: redesigned `ok_check` / `cancel_x` in `host/assets/make_icons.py` as bold WHITE
  glyphs (they now sit on the saturated statusOk-green / neutral button fills, so white
  reads on light + dark; the old palette-colored glyphs were near-invisible on the pill).
  Regenerated `atlas_light.png` / `atlas_dark.png` (atlas.json UVs unchanged — only the
  two cells' pixels changed). These two glyphs are used ONLY by the PM chrome buttons.
