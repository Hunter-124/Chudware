## Context

Pillar 20 capstone. Prove the thesis with numbers: the same mission ("bearing mount
bracket: Ø20 g6 shaft, sliding fit bore, 4x M5 base holes, aluminum, machined, FEA
sanity under 500 N side load") run (a) baseline loop, (b) advisory loop with roles,
on (1) a local 24k model and (2) sonnet-class. Metrics: iterations-to-converge,
check failures per stage, escalations, token spend, final verify_battery verdict.
This is the go/no-go evidence before deeper investment (and the Pillar 16 telemetry
pattern for advisory training data).

- `tools/flywheel/bench/benches/advisor_e2e.py` — new bench + mission spec fixtures

- telemetry: advisory-shown → action → check-outcome triples logged via existing

## Steps

1. Read the architecture doc; confirm merged state of W2/W5/W7/W8 (work_board) and
   feature-flag off anything unmerged rather than blocking.
2. Mission spec as fixture (requirements JSON so runs are reproducible; no
   Date.now-style nondeterminism in metrics ids).
3. Runner: baseline = current run_turn; advisory = orchestrator role over DAG with
   role nodes; identical mission, provider, iteration caps. Capture per-iteration:
   stage, advisories shown (ids), action taken, check outcomes, tokens.
4. Score with deterministic checks only: verify_battery verdict, fit_calc conformance
   of the bore dimension, hole pattern correctness via doc queries, FEA margin verdict
   (T-W9 if merged, else raw scalar threshold).
5. Run matrix (local endpoint if available; else sonnet + a small hosted model, and
   document the local-run recipe — offline discipline, no all-skip): 2 loops × 2
   tiers × 3 seeds. Emit comparison markdown + JSON.
6. Log the advisory triples through telemetry (consent-tier aware) — this seeds the
   Pillar 16 next-action dataset.
7. Append results + honest analysis (including regressions) to the architecture doc;
   post summary via note on this task.
