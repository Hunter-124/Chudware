## Context

Pillar 20 Part II (docs/ADVISOR_ARCHITECTURE.md §2.12, contracts/advisor.md §12 §14 —
FROZEN). Hunter directive: with multiple model sources, a higher model orchestrates
lesser models as sub-agents; sub-agents may spawn sub-sub-agents only with approval
from the mission overseer; preferences are user-configurable (GUI settings, T-W17
builds the UI on top of routing.yaml). Budgets inherit down the tree; the tree is a
ledger artifact.

## Steps

1. Read docs §2.12, contract §12 §14. Shapes frozen. Pillar 12 constraint stands:
   NO consumer-subscription OAuth reuse — sources are API-key/local/session-auth
   providers only (existing providers/ package).
2. Routing: parse/validate routing.yaml; resolve `strongest`/`cheapest` against
   configured sources by a documented capability ranking (context length + a static
   provider-tier table; keep it data, not code); availability probe with fallthrough
   (local source offline → next preference); every resolution is a ledger event
   ("sketcher → qwen3-4b@lmstudio because local-first preference").
   Hunter directive 2026-07-04 (contract §14 addendum): routing.yaml is the ONLY
   place role→model bindings exist — no hardcoded role model choices anywhere,
   no special-casing the overseer in code; expose a `resolve_assignments()` API
   returning the per-role resolved models so the T-W17 settings GUI can display
   them live.
3. Delegation: `delegate(role, brief, budget)` tool available to roles per card
   policy; depth-1 from orchestrator auto-approves; deeper → approval request to the
   mission overseer (T-W13 audit_now with trigger=manual, scope=delegation) or human
   per policy; pending requests block only the requesting agent, never siblings.
4. Budget inheritance: child spend accrues to all ancestors (single counter tree);
   harness revokes (status=revoked, handoff forced) when any ancestor grant is
   exhausted; revocation produces a failure-card-style ledger event.
5. Sub-agent lifecycle: spawn = role card + tier resolved via routing + brief +
   ledger access scoped per card; completion = validated handoff (T-W7) appended to
   parent's context by reference (ledger seq, not inline dump).
6. Tests: approval matrix (auto/overseer/human × depth); budget accrual + revocation
   at exact exhaustion; routing fallthrough when a source is down; resolution ledger
   events; depth cap; single-source degenerate case (everything collapses onto one
   model but tree/budgets still function).
7. MCP freshness + `graphify update .`.
