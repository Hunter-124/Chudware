## Context

Pillar 20 Part II (docs/ADVISOR_ARCHITECTURE.md §2.13, contracts/advisor.md §13 —
FROZEN). Hunter directive: model drivers need a DAG to plan parts/features in the
correct order so nothing is missed on complex components. A deterministic planner
turns a build plan (loop.py PLAN_PROMPT output shape / dag_plan mission) into an
aicad.buildgraph/1 graph with declared prerequisites; a validator catches missing
prerequisites, cycles, and dangling refs BEFORE building; the executor walks it
topologically with per-node status.

## Files / areas touched

- `services/agent/buildgraph/` — new package: `schema.py` (validate), `planner.py`
  (plan → graph), `rules.py` (prerequisite rules as data), `executor.py` (topo walk,
  status, fan-out hooks)
- `services/dag/` seam — dag_plan gains a modeling-mission path that emits buildgraph
  nodes; dag_status includes node statuses
- `services/mcp/` — `buildgraph_plan(plan_json)`, `buildgraph_status(run_id)` tools
- `services/agent/loop.py` seam — optional: plan_first path routes through the
  planner and injects the ordered checklist into the opening prompt
- tests: `services/agent/buildgraph/test_buildgraph.py`

## Steps

1. Read docs §2.13 + contract §13. Shape frozen.
2. `rules.py` — prerequisite rules as DATA (rule id, matcher, requires, why):
   datum/reference geometry before dependent sketches; base solid before its
   modifications; boss before blend/pierce features touching it; shell after the
   features it must hollow around (or explicit before with why); patterns after
   their seed; per-part chains independent; parts before mates; mates before
   assembly verify; verify joins after all fan-out branches; checkpoint nodes at
   part_done/mission_done (aicad.plmlink/1 triggers — emit the event shape even if
   PLM vault absent).
3. `planner.py` — consume both input shapes: loop.py BUILD PLAN JSON (parts[] with
   features[]) and dag_plan mission specs. Infer edges from rules + explicit
   feature references; every edge carries `why`.
4. `schema.py` validator — cycle detection, dangling requires, refs resolvable
   against the plan, orphan features (in plan but unreachable), missing joins.
   Findings emitted as aicad.advisory/1 items (this is the plan-audit hook).
5. `executor.py` — topological order with parallel-ready sets (fan-out for
   multi-part: expose `ready_nodes()` so the harness can assign nodes to
   sub-agents), status transitions, failed-node policy (block dependents, mark
   skipped with reason, surface as advisory).
6. Wire the two seams (dag_plan modeling path; loop.py ordered-checklist injection)
   behind flags, minimal changes.
7. Tests: rule inference on a fixture plan (bracket: base→boss→bore-through-boss→
   fillet, 4-hole pattern after base); validator catches a plan missing the boss
   (bore has dangling requires); cycle fixture; parallel ready-set on a 3-part
   assembly plan; executor status walk.
8. MCP freshness + `graphify update .`.
