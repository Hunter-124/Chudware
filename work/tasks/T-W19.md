## Steps

1. Read the pipeline doc end-to-end, then §16/§17. Phase contracts and context
   recipes are specified — implement, don't redesign.
2. `manifest.py`: validate per §16 (≥1 criterion per deliverable; every criterion
   names an executable check tool; manual-kind pairing rule; modification
   target_refs resolve via doc queries; dependency cycles). Bounce-once-then-
   escalate on role failures (intake_analyst escalation_policy).
3. `phases.py`: phase enum + transitions per the doc §1; exit gates call the named
   checks (manifest valid; no blocking ambiguity; spec audited + criteria covered;
   graphs valid + ratified; per-node gates via foreman; all criteria PASS or
   waived-by-name). Phase state and transitions are ledger stage_log events.
4. `replan.py`: §17 routing table (approach→orchestrator; buildgraph→orchestrator+
   overseer audit; spec→overseer(+user if criteria change); requirement→user);
   approved → dag_replan/buildgraph edit + ledger event; denied → returned with
   reason; blocked-urgency freezes only the requesting node's branch.
5. DAG mission template: phases as nodes, role field per node (cards loaded from
   services/agent/roles/ VERBATIM — never inline prompts in code), fan-out at
   Phase 4 via buildgraph ready-sets + workspace leases (T-W16 if merged, else
   sequential fallback behind a flag).
6. `run_mission` + MCP tools; mission_status renders from ledger (what mission
   control and the GUI consume).
7. Tests: manifest validator rule-by-rule (fixtures for each §16 rule); phase gate
   enforcement (cannot enter BUILD with unratified plan); replan routing matrix
   incl. criteria-change→user; end-to-end dry run with mock providers through all
   8 phases on a single-part fixture (offline discipline: mocks exercise real code
   paths, no all-skip).
8. MCP freshness: server instructions gain the mission pipeline section;
   `graphify update .`.
