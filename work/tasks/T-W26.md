## Context

Hunter 2026-07-04: pack the llama.cpp binary into the program and install it with a
cutting-edge small model so the token-hungry Pillar 20 workflows (councils, ladder,
ponders, trigger packs) run free locally. In-app pivot applies. The providers package
already speaks to a llama.cpp server; what's missing is BUNDLING (ship/manage the
binary), MODEL PROVISIONING (download/verify/store GGUFs), and lifecycle (auto
start/stop, port mgmt, n_ctx → tier detect).

## Files / areas touched

- `services/agent/local_runtime.py` — new: llama-server lifecycle (spawn/health/stop,
  port allocation, n_ctx config feeding tiers.detect_tier), binary discovery
  (bundled path → system PATH fallback)
- `tools/package/` or build seam — vendor/fetch strategy for the llama.cpp binary
  (Linux first; Windows seam documented). llama.cpp is MIT — record in
  contracts/license_debt.md if vendored
- `services/agent/model_manager.py` — new: model registry (id, HF repo, file, quant,
  sha256, ctx), download with checksum verify + resume, storage under app data,
  `provision(model_id)` + `list_models()`
- routing seam — provisioned bundled runtime appears as a source in routing.yaml
  (kind: llamacpp, auto-added on first provision; user-editable per §14)
- tests: `services/agent/test_local_runtime.py` (mock server + live recipe)

5. Tests: registry/checksum/resume with a tiny dummy GGUF fixture; lifecycle with a
   mock server; LIVE smoke recipe documented (download real model, run sketcher bench
