## Context

T-W30 proved the execution path end-to-end with a real local model (qwen3-4b,
prompted-JSON directives parse clean; verify gate honestly routes FAIL→CORRECT).
All gym REAL cycles still score 0.000 — the finisher's diagnosis names the two
mechanical blockers, both scoped here:

1. **Tool-schema blindness** (top lever): models call real tools but guess kwargs.
   Inject trimmed tool schemas into the turn prompt's §9.1 tools slot —
   `tiers.trim_tool_schema` already exists; wire it per-node from the role card's
   tool allowlist so the prompt stays inside the tier's context budget.
2. **Run-scoped dispatcher**: `ledger_get/ledger_note`, `dag_plan`, `ask_user`,
   `delegate`, `part_search` cannot resolve from the process-wide battery/research
   registry — they need mission context (the run's ledger handle, doc ids, board
   seams). Add a mission-scoped dispatch layer that agent_turn consults before the
   global registry.

Also sanctioned by the foreman (2026-07-05): add a dedicated `execution_stall`
failure-taxonomy class so pre-BUILD stalls stop mis-classifying as
`incoherent_geometry` with empty evidence. (Taxonomy data change only — role-card
prompt wording stays lead-owned.)

What the two shipped levers fixed, observed live:
1. Zero `could not be resolved` errors (r3: ~30 across the six families + gsl/
   parts/buildgraph). ledger_get/ledger_note/ask_user/part_search/delegate/
   dag_plan all dispatch mission-scoped; describers/parts/preflight/regen/
   buildgraph/intake/req/cost/structural/workspace resolve globally.
2. Zero `unexpected keyword argument` errors (r3: every mutating call). With
   schemas in the prompt the model emits well-formed kwargs; error feedback
   loops now visibly self-correct (e.g. ledger_note kind 'audit' -> retried
   with valid kind two calls later).
3. Bonus live catch: the PLAN node emitted a valid nested-args buildgraph_plan
   call that the old brace-pair regex DROPPED as free text — fixed
   (_parse_directive raw_decode; 7d8d7700).

Remaining blockers to a real pass (in observed order of impact):
1. **Spec-in-handoff instead of ledger writes** (all 3 seeds): spec_writer
   emits its full spec inside the `done` handoff; the honest SPECIFY gate reads
   ledger dimension events and correctly fails (`specify_incomplete`). Lever is
   role-card prompt wording (lead-owned) and/or playbook step_locked enforcement
   actually wired into the turn loop (harness follow-up — the tier dial exists
   but agent_turn does not step-lock).
2. **Invented ids**: the model fabricates run_id/doc_id args (e.g.
   "flanged_bushing_design_20231005"). Mission-scoped tools ignore the wrong
   run_id (bound to the run), but engine tools (describe_part,
   buildgraph_status) fail semantically. Follow-up lever: inject the actual
   run_id/doc ids into the node request or §9.1 state slot (mission_template).
3. delegate refuses by design (no org tree in a flat mission) — the model
   retries it; role cards for flat missions could drop delegate from allowlists
   (lead-owned).
